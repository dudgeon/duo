Canvas actions demo

Three live buttons exercising the data-duo-action vocabulary added in v0.3.0. Click each one and watch what happens in the rest of the workspace.

Trust gating: these buttons fire because this file lives under ~/.claude/duo/. Canvases anywhere else stay inert in v0.3.0 — see the FAQ entry on canvas actions for the full trust model.

1. claude:spawn — open a new Claude tab

Adds a fresh terminal tab, kind = claude, and auto-launches Claude Code in it. The shim wraps the launch with --append-system-prompt so the new agent arrives Duo-aware.

Optional: data-cwd="…" to override the navigator pending CWD; data-cmd="…" to pre-type a prompt before claude takes over. 
<button data-duo-action="claude:spawn">Spawn a Claude tab</button>

2. terminal:send — write into the active terminal

Pipes text into whatever terminal tab is currently active. By default leaves the cursor parked at the prompt so the user confirms by pressing Enter; pass data-enter="true" to submit on their behalf.

<button data-duo-action="terminal:send" data-text="duo --version" data-enter="true">
  Run duo --version
</button>

3. browser:open — open a URL in the embedded browser

Opens a new browser tab with the given URL. Routing follows the same logic as duo open: hostnames in ~/.claude/duo/external-domains.json punt to the system browser instead.

<button data-duo-action="browser:open" data-url="https://docs.claude.com/claude-code">
  Open Claude Code docs
</button>

Authoring notes

Action elements can be <button>, <a>, or any other tag — Duo walks up from the click target to the nearest ancestor with data-duo-action. Clicks inside the action element are intercepted before contentEditable gets a chance to move the cursor, so you can use them inside editable canvases too. Modifier-clicks (⌘, ⌥, ⇧, ⌃) and middle-clicks pass through unchanged so users can copy text or open in a new browser tab as usual.

Malformed markup is logged to the canvas console (with a [duo-canvas-action] prefix) so authors can iterate quickly without an inspector. Untrusted-canvas clicks emit a quiet console.info rather than firing the action — clear in dev, silent in production.
