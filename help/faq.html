v0.6.10 — Image handling (paste / view / CLI) + Save clarity + Obsidian autocomplete 2026-05-09

Three sprints in one cut. Sprint 10 (SaveControl pill + autosave toggle) and Sprint 11 (Obsidian-style [[/@/⌘O autocomplete cluster + the file-changed-on-disk false-positive root-cause from BUG-104/107) accumulated since v0.6.9; Sprint 12 was course-corrected mid-flight when a prior cloud agent shipped image VIEWER chrome (ENH-111) instead of paste-image (ENH-108, the actual ask) — both ship together. Pre-v0.6.10 path for inserting an image into a markdown doc was save-to-Desktop → drag-to-Finder → markdown-link-by-hand. After: ⌘V works in both markdown editor and the HTML canvas; duo image insert works from the agent.

  • Paste-image into the markdown editor + canvas (ENH-108). ⌘V or drag-drop an image (PNG, JPG, GIF, WEBP, SVG, BMP, TIFF) into either editing surface. Image saves alongside the active doc as image-<YYYYMMDD-HHMMSS>-<hash>.<ext> and inserts inline. Untitled buffers warn-and-decline. v1 trade-off: markdown source carries ![](blob:...) URLs which render immediately on paste but die on doc reload — v2 (custom NodeView with persistent abs paths) is queued as FOLLOWUP-014.
  • Image viewer v2 (ENH-111). Toolbar over the image area: zoom in/out (+/−, ⌘/⌃-wheel), click-toggle fit/manual, fit-to-window, 1:1 actual size, copy-image, dimensions + file-size readout (e.g. "1440 × 900 · 312 KB"). Right-click → native context menu (Copy image / Copy path / Open in default app / Reveal in Finder / Fit / 1:1). Drag-pan when zoomed past container.
  • duo image insert <path> [--alt "…"] CLI verb (ENH-108). Agent-driven image insertion: source bytes copied alongside the active markdown editor's doc, inserted at caret. v1 markdown-editor target only — canvas CLI parity deferred to ENH-125.
  • SaveControl pill + autosave toggle (ENH-103 + ENH-104). Replaces the prior "Saved/Saving…" text + Save button with a single four-state pill (Saved · Save · Saving… · Failed-retry). Both editor and canvas surfaces. Hover-reveal autosave on/off toggle adjacent. Per-app preference, cross-tab sync.
  • Obsidian autocomplete cluster (ENH-096 B.2/B.4 + ENH-105). Type [[ in a vault file → fuzzy-match popup against vault files; ↑↓/Tab/Enter to insert as [[Basename]]. Same UI on @ mention (inserts canonical [[wikilink]] form for unified vault round-trip). ⌘O opens a centered overlay sourcing the same vault index. .obsidian/ directory always visible in navigator (ENH-109). cmd+click on [[Does Not Exist]] creates the file (ENH-114, Obsidian parity).
  • Markdown table-cell copy yields the cell text, not [table] (BUG-108). New TipTap extension intercepts clipboard text serialization for slices that begin with a table node — returns plain text with newline between rows + tab between cells. Whole-table selections still serialize as proper markdown tables.
  • "File changed on disk" false-positive on first edit (BUG-104 + BUG-107) — root-caused after recurring across walks for several sprints. tiptap-markdown's serializer normalizes trailing whitespace on round-trip; # Index\n\n from disk parses then re-serializes as # Index\n. The pre-save reconciliation check now normalizes trailing whitespace before comparing, so any file with a trailing blank line stops false-positiving. Real conflicts (substantive content drift) still surface the banner.
  • Terminal-tab right-click → Reveal in navigator (ENH-115). Context-menu entry on terminal tabs jumps the file tree to that tab's CWD and surfaces the reveal chip. Reuses the existing duo reveal flow.
  • Smoke-walk page no longer silently overwrites your edits across walks of the same version (BUG-110). The smoke-walk skill's localStorage key now derives from the manifest filename instead of the bare version. Sprint 11's wikilink walk and Sprint 12's image-viewer walk no longer fight for one storage slot.
  • Renderer console.* forwarded to dev stdout (ENH-121, dev-only). Every console.log/warn/error from the renderer prints to dev terminal as [renderer:level] (file:line). Filters Vite + Electron-security noise. Single highest-leverage observability addition this year — Sprint 12's 90 minutes of futile image-render diagnosis would have been ~5 minutes with this in place.

Known issues / v1 trade-offs: paste-image markdown source carries ![](blob:...) URLs (FOLLOWUP-014, non-portable across reload); duo edit doesn't auto-focus the opened tab (BUG-101 — workaround: click the tab); Escape on [[/@ autocomplete has a portal-cleanup race (workaround: type any char or press Enter). Deferred to Sprint 13+: canvas duo image insert CLI parity (ENH-125), image-handling polish (ENH-118/119/120), view-source for markdown/HTML (ENH-117), renderer DevTools tooling (ENH-122/123/124), JSON viewer (ENH-110).

  • Wikilinks cmd+click navigation, finally working (ENH-096). Two root causes uncovered across walks. Walk-0: the click handler bailed because event.target is a Text node when the click hits visible text inside the decoration span — closest is undefined on Text nodes. Extracted resolveWikilinkTargetAtClick that walks up via parentElement + falls back to a pos-based decoration lookup. Walk-1: the resolver couldn't find the vault root — findVaultRoot was using files.exists (regular-files-only per BUG-039 semantic) to detect .obsidian/ (a directory). Added files.dirExists sibling. cmd+click now opens the linked file from the resolved vault root.
  • Pane-jump chord set + duo focus-pane CLI (ENH-098). ⌘⇧L → terminal, ⌘⇧; → main working pane, ⌘⇧' → split-view aux. Distinct from ⌘` which CYCLES — the new chords JUMP directly to a named pane. CLI parity via duo focus-pane <terminal|main|aux>. Originally specced as ⌘⌥L/;/' but re-picked at walk-1 (system-level window managers like Raycast intercept meta+alt before the renderer sees it). Walk-2 surfaced a deeper visibility bug — BUG-046 keeps every file-tab renderer mounted (display-toggled), and naïve selectors hit hidden tabs. Built a visibility-aware editor finder (findVisibleWorkingPaneCE) that filters by offsetParent !== null AND scopes to inside-/outside-aux via a new data-duo-workingpane-aux marker.
  • duo edit reliably surfaces the new tab + lands the caret in the editor (BUG-101 editor-routed half). Three layers of bug. (1) React anti-pattern: setActiveWorking nested inside the setFileTabs updater let React 18+'s automatic batching land setters in different renders. Lifted to a pendingActivationRef + post-updater flush. (2) DOM-level .focus() on the editor's contentEditable wasn't firing — added a two-rAF chain mirroring newBrowserTab's address-bar dance. (3) The selector race from above (BUG-046's mounted-but-hidden tabs). Routed through the same visibility-aware finder. Now: tab activates, caret lands, first keystroke writes into the file. The browser-routed half (duo open https://...) is the same shape on a different code path; carries to Sprint 10.
  • ⌘⇧⌫ deletes the active file (with confirm) (ENH-102). Mirrors the right-click → Move to Trash flow on a working-pane file tab. Browser tabs and terminal tabs explicitly out of scope (⌘W handles tab close). Soft-success on ENOENT — file's gone, user's intent is still "close this tab."
  • ⌘T new browser tab — caret lands in the URL bar (BUG-103). Owner's diagnostic was the smoking gun: document.activeElement WAS the address bar input (DOM focus correct), but the input's caret rendered grey/inactive — meaning OS focus stayed on the new browser tab's WCV. Fix: call keyboard.reclaimFocus() before the rAF chain to pull OS focus from the WCV to the renderer; URL input's caret renders blue/active.
  • Distro Pack Builder Workshop (ENH-106). New repo-only distro-pack-builder/ folder ships a guided tutorial for first-time pack builders: scoped CLAUDE.md, README, 11-step playground.md walking scaffold→customize→validate→build→smoke→distribute, project-scoped assistant skill at .claude/skills/pack-builder-workshop/.   • BUG-056 pill gating regression — now AUTOMATED. The in-page Send → Duo pill must NEVER render without an active Claude session. This has recurred across multiple walks because the gating (if (!window.__duoClaudeLive) inside the CDP-injected IIFE) was tested only by manually walking the negative case. Owner-flagged at walk-2: "why am I walking this every cut, please test it." Added electron/cdp-bridge.test.ts with three asserts on the IIFE source (literal guard text present, sits before ensurePill(), exactly one active read-site). Removed from the smoke-walk skill's mandatory-items section.
  • ENH-091 caret seed for fresh canvases — deferred indefinitely. Walk-2 traces showed the seed APPLIES correctly AND sticks across the next animation frame — but typing still lands in the H1 title. The override fires AFTER rAF (after Chromium's internal layout pass), unfixable without a different architectural approach. Owner directive: low priority, do not revisit until a console smoking gun surfaces. Diagnostic instrumentation stays in code.

  • Bullet anchor decoration + thread distinctness (BUG-088 / BUG-090 / BUG-087). Pre-fix, Enter on a bullet cloned the source <li>'s data-duo-id and the auto-stamp observer skipped the duplicate, so multiple bullets shared one anchor and comments collapsed into a single thread. The auto-stamp now detects duplicates: first-in-document keeps its id, later siblings get a fresh ULID. With unique anchors, rail-click activates exactly the right element.
  • Move to Trash on a missing file silently closes the tab (BUG-098). The trash IPC errors when the file is already gone (deleted by another tool, or never written). Now treated as a no-op success — the tab closes, no error dialog. Other error classes (permission denied, etc.) still surface.
  • Aux tab focus no longer steals main pane focus (BUG-095). Clicking inside an aux'd browser tab no longer kicks the main pane's editor / canvas out and switches it to a different browser tab. Aux click → aux focus glow only.
  • Closing the last main-strip browser tab no longer blanks aux (BUG-096). Aux pane stays put; if only the aux tab would remain, a fresh about:blank spawns in main.
  • Canvas anchor decoration no longer flickers while typing (BUG-089). Removed the 100ms CSS transition that restarted on every keystroke.
  • Worksheet / smoke-walk pages stay read-only in canvas (BUG-091 + worksheet-promotion). Combined with Phase 3c, the rev3 walk's procedural blocker (worksheet usable in split view) is fully resolved.
  • Right-click "Move to Split View" works on browser tabs (BUG-091). Was excluded; now included with kind-aware routing.
  • BUG-093 instrumentation. <ErrorBoundary> extended with inline / label / Try-again retry; wrapped <WorkingPane>; structured [BUG-093] traces in splitViewMoveTabByPath. The rev3 right-click-crash now scopes to a localized error panel (terminal column / file tree / banners stay alive) AND will name itself when it next fires.
  • arm64-only macOS builds. Intel/x64 dropped from the build matrix. ~2.6 GB of Intel artifacts cleaned, ~1.85 GB freed on GitHub Releases. Cut times drop ~50% per release.

Known issues. BUG-097 — markdown editor empty-doc placeholder wraps narrow on first load (cosmetic; type any character to clear). BUG-093 — right-click → Move to Split View can still crash the renderer; now scoped to a localized panel and instrumented for next-repro diagnosis.

Working with files

Can I open my Obsidian vault in Duo?

Yes. Duo's navigator opens any folder, and the markdown editor handles standard markdown — your YAML frontmatter (tags: [...], aliases: [...], cssclasses: [...], custom properties) is preserved verbatim through every save. The .obsidian/ config folder stays hidden in the navigator (Duo hides dotfiles by default) and is also ignored by Duo's file watcher so workspace-state writes from a concurrently-running Obsidian don't churn through Duo's reload pipeline.

Concurrent editing is safe: BUG-085's external-write reconciliation means if Obsidian saves a file you have open in Duo, Duo silently reloads on a clean buffer or surfaces a Reload-from-disk / Keep-mine banner if your buffer was dirty.

Wikilinks ([[Page Name]]) — v0.6.8+: rendered as Atelier-styled clickable spans. Cmd+click opens the linked file from the resolved vault root (Duo walks up from the active file's directory until it finds a .obsidian/ folder, falling back to the navigator CWD). Click resolution uses Obsidian's name-first semantic — same shorthand [[Foo]] finds Foo.md anywhere in the vault.

What still doesn't render: embeds (![[Page]]), block references ([[Page#^block]]), inline tag pills (#tag shows as plain text), callouts (> [!note] renders as a plain blockquote), math ($inline$), Mermaid diagrams, daily-notes shortcut, and the graph view. These are queued for follow-up sprints. Obsidian-specific features (plugins, themes, the canvas .canvas file format) are out of scope.

What are the .duo.json files next to my notes?

When you add a comment to a markdown file or HTML canvas in Duo, the comment metadata is written to a sidecar at <file>.md.duo.json (or <file>.html.duo.json for canvases). The sidecar carries the comment body, an excerpt of the anchored text, and a small slice of context before/after so the anchor can re-resolve when you reopen the file. The source file itself stays clean — comments never mix into the markdown / HTML on disk.

For git-tracked vaults / repos: add *.duo.json to your .gitignore if you'd rather the sidecars stay local. They're per-machine annotations, not collaborative content. If you DO want them tracked (say, to share comments across a team's vault), commit them as-is — they're plain JSON and merge cleanly.

Removing them: deleting a sidecar removes its associated comments on the next open of the file. Duo never re-creates a sidecar for a file with no comments.

Getting started

How do I install Duo?

v0.1.0 is pre-distribution. To run it: clone the repo, npm install, then either npm run dev for the live build or npm run dist to produce an unsigned macOS DMG. First-launch self-install (auto-installing the duo CLI and the skill / subagent into ~/.claude/) ships in v0.2.0.

The terminal says "claude not found" — how do I fix that?

Duo expects the claude binary on your PATH (Claude Code CLI). Install it via npm install -g @anthropic-ai/claude-code or whatever the current install instruction is for your environment. Duo re-checks which claude on every new tab spawn, so a fresh terminal will pick up the installed binary.

How do I run duo commands from Claude or my own scripts?

The duo binary lives at cli/duo in the repo. For dev use, either invoke it directly (./cli/duo help) or symlink it onto your PATH (ln -s "$(pwd)/cli/duo" /usr/local/bin/duo). The Stage 18 first-launch installer will do this automatically when distribution begins.

Note: duo talks to Duo's main process over a Unix socket. It only works when Duo is running.

Using Duo

How do I open or create a markdown file?

Click any .md file in the file navigator (left column) to open it as the rich editor. To create a new one: click + on the working-pane tab strip, type a filename ending in .md, and hit Enter.

How does the HTML canvas work?

Open any .html file from the navigator and it renders as a live, editable canvas — what you see is what gets saved. The same toolbar as the markdown editor (heading picker, lists, tables, etc.) plus markdown shortcuts on typing. Comments live in a sidecar (<file>.html.duo.json) and never mix into the saved HTML. Claude can edit the canvas structurally via duo html * commands.

What is the "Send → Duo" pill?

When you select text in the markdown editor, the browser pane, or the HTML canvas, a small "Send → Duo" pill appears beside the selection. Click it; the selection lands in your active terminal as a formatted quote with provenance (path / URL trail) so Claude knows where it came from. Three formats available via duo selection-format a|b|c.

What's the difference between + and > on the terminal tab strip?

+ opens a Claude Code session in a new tab (auto-launches claude). > opens a vanilla shell. Keyboard equivalents: ⌘T always opens a new browser tab (Chrome parity), ⌘⇧T opens a Claude tab from anywhere.

Why did clicking a link send me to my default browser?

Off-host URLs go to your default browser via shell.openExternal — the assumption being that work-restricted sites (SSO, internal pages, bookmarked tools) live on your real browser, not Duo's embedded Chromium. Domains on the external-domains list get this treatment automatically. Add or remove domains by editing ~/.claude/duo/external-domains.json.

How do I switch between light and dark themes?

The theme button is in the title bar (top-right). Click "System" / "Light" / "Dark" to cycle. From the CLI: duo theme system|light|dark.

For Claude / agent users

How do I ask Claude what Duo can do?

The What Duo does page lists every capability with a use case and the CLI invocation. From a Duo terminal, duo help dumps the full verb reference. Claude knows about both — just describe what you want and let it pick the right tool.

What is the Duo subagent?

A specialized Haiku-powered agent that handles mechanical Duo work (find this element, summarize the selection, route a quote to a terminal). Triggered automatically by Claude Code when the task fits — keeps Sonnet's working memory free for the actual problem you're solving.

How does Claude know it's running inside Duo?

Every PTY Duo spawns gets DUO_SESSION, DUO_SOCKET, DUO_VERSION, and TERM_PROGRAM=Duo in its environment. Tools branch on these. To check from a terminal: echo $DUO_SESSION — if it's non-empty, you're inside Duo.

Troubleshooting

Why does duo silently fail in some Claude Code sessions?

Claude Code runs each Bash tool call inside a macOS Seatbelt sandbox that gates Unix-domain-socket connections. Duo's bridge is a Unix socket — so duo commands invoked from a sandboxed Claude Code session can hang or return ECONNREFUSED. Workaround: invoke duo from a Duo-spawned terminal directly (those PTYs aren't sandboxed). The sandbox-tolerant transport ADR (in docs/DECISIONS.md) tracks the long-term fix.

Why doesn't ⌘T open a Claude tab when I'm in a terminal?

It used to (Stage 19c spec) but no longer does (BUG-008 spec resolution, 2026-04-26). ⌘T is now always a new browser tab regardless of focus — Chrome parity. To open a Claude tab from the keyboard, use ⌘⇧T. To open one from the UI, click + on the terminal tab strip.

The xterm-eats-keystroke issue that caused BUG-008 was also fixed in the same ship: every Duo-global keyboard shortcut now reaches its handler from terminal focus.

I clicked + for a Claude tab and the prompt is just showing "claude" without running.

Known issue (tasks.md § BUG-009). The auto-launch wiring writes claude\n too early — before the shell prompt is ready — so the newline gets dropped. Workaround: press Enter manually. Fix lands in v0.2.0.

What does the welcome banner install?

One click copies four things into your home directory:

  • ~/.claude/skills/duo/ — the Duo skill (so any Claude Code session in any directory discovers Duo's CLI).
  • ~/.claude/agents/duo.md — the Duo subagent (Haiku 4.5; specialized for mechanical Duo work).
  • ~/.claude/duo/help/ — local copies of FAQ + What Duo does (so you can customize them; the bundle copies still serve as fallback).
  • ~/.local/bin/duo — the duo CLI binary.

Plus a provenance file at ~/.claude/duo/installed.json with the version + timestamp. Idempotent — re-running on an upgrade overwrites everything and re-stamps the version. ~/.claude/duo/external-domains.json is bootstrapped if absent and never clobbered (it can hold your own customizations).

The banner says my $PATH is missing ~/.local/bin — what do I do?

Add this line to your ~/.zshrc (or ~/.bashrc if you use bash):

export PATH="$HOME/.local/bin:$PATH"

Then open a fresh terminal (or run source ~/.zshrc in an existing one). duo help should now work.

You don't need this for Duo's UI to work — only for invoking duo from arbitrary terminals (including Claude Code sessions running outside Duo).

Why do special characters look broken when I paste into the terminal?

Multi-byte Unicode characters (em-dash, ⌘⌥, ñ, emoji, etc.) come out as raw bytes when your shell's locale isn't UTF-8. Most common cause: conda's (base) activator sets LC_ALL=C, which strips UTF-8 awareness from anything that runs after it.

Quick check from any terminal:

locale | grep -E 'LC_ALL|LC_CTYPE|LANG'

If you see C or POSIX in any of those, fix it by adding this to your ~/.zshrc (or ~/.bashrc) — after the conda conda init block, not before:

export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8

Open a fresh terminal. The locale gotcha affects every terminal paste on your machine, not just Duo's — TextEdit and other GUI apps round-trip multi-byte characters fine because they don't go through a shell.
