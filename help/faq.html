v0.6.3 — Native menus, collapse panes, line numbers in progress · 2026-05-02

This block is a preview of v0.6.3 work that's shipped + verified on the dev branch but not yet cut. It updates as items land and freezes when the version is cut. Two architectural / feature wins plus a punch list of long-overdue UX paper-cuts that earned their way in via two smoke walks.

  • Native right-click menus + system confirmation sheets (ENH-050). Every right-click on a tab, a file in the navigator, or a pinned-nav row pops a real macOS NSMenu instead of an in-renderer styled menu. Trash, pinned-close, and ⌘W-on-unsaved confirmations drop as native sheets from the titlebar. macOS handles the rendering at the window-server level, which means menus and sheets now composite correctly above the embedded browser pane — no more "menu cut off mid-list" or "modal disappears the browser" jankiness. Trade-off: those specific surfaces (menus + destructive confirms) lose Atelier styling and follow the OS theme. Everything else (canvas, editor, info popovers, banners) keeps Atelier.
  • Collapse panes (ENH-040 + ENH-066). Two new buttons in the titlebar, next to the theme toggle, hide the terminal column or the canvas (right pane) all the way. The collapsed slot becomes a clickable 36px vertical bar with a glyph and a sideways "terminal" / "canvas" label. Click it to restore — and Duo remembers your previous split percentage so you don't snap to 50/50.
  • Tab reorder (ENH-042). Drag any working-pane tab horizontally onto another to reposition; or right-click → Move tab left / Move tab right. Pinned tabs stay leftmost; the menu hides options at zone edges (no "Move right" on the rightmost tab).
  • Toggleable line numbers in the markdown editor (ENH-069 + ENH-071). A small # button in the bottom-left of the editor toggles a gutter that numbers each block (paragraphs, headings, list items, blockquotes). Persists across sessions per-user. v1 caveat: counts blocks, not visual wrapped lines — long paragraphs that wrap count as one.
  • Smart duo open (BUG-067). duo open ~/path/to/file.md now opens in the markdown editor instead of the browser pane. HTML files with <meta name="duo-open-in" content="browser"> still open in the browser; everything else opens in the editor. URLs unchanged. The CLI response carries an accurate routedTo label.
  • Smoke-walk page persists in-flight notes (ENH-038). Your Pass / Fail toggles + per-item notes textareas now write to localStorage on every keystroke and restore on every page load. A new "Clear saved walk" button wipes the state after you've copied results back. Survives accidental refresh, the dual-instance blank screen we used to hit, and full Duo restarts.
  • Project Claude context, collapsible + auto-named (ENH-045a). The navigator's project pane now shows a collapsible section labeled {project-name} Claude context — folder name by default, or package.json's name field when present. Defaults collapsed; toggle persists.

Polish that punched up: globe glyph for new-browser-tab button (ENH-068); duo/ in "Your Claude settings" alongside CLAUDE.md / skills / agents (ENH-067); "Copy path" item in tab right-click menu (ENH-074); visible separator between tab strip and the sticky new-tab cluster (ENH-073); larger collapse-rail labels (ENH-072); auto-injected Copy buttons on canvas <pre> blocks documented for canvas authors (ENH-046).

Bug fixes that landed: two flavors of file-tab de-duplication (renderer + CLI, BUG-059); fenced code blocks materialize on Enter in the markdown editor (BUG-060); ⌘⇧G no longer blanks the entire app (BUG-065 — Rules-of-Hooks violation latent since v0.5.4 + a defensive ErrorBoundary so future render errors surface as a fallback panel instead of a blank window); the clawd glyph isn't clipped or hardcoded-orange anymore (BUG-066); sticky new-tab cluster no longer scrolls off-screen under heavy panning (BUG-068). Plus BUG-058 (originally fixed via a WCV-mute) properly retired now that ENH-050's native menus replace the in-renderer ContextMenu.

Why this isn't cut yet: owner direction. Accumulating until the next "chapter ends" signal — likely after a Sprint 3 sweep through v0.6.4 candidates (clickable smoke-walk paths, the BUG-061 bullet-trigger Chromium fix, fresh-canvas-cursor-doesn't-land bug, ⌘[ / ⌘] in canvas). The work above is done and stable.

v0.6.2 — The lesson template ecosystem completes 2026-05-02

The closing chapter of the canvas-authoring → lesson-template arc that started in v0.6.0. The linear lesson template shipped in v0.6.1; v0.6.2 lands its sibling (the curriculum template, for multi-canvas packs) and the fly-through harness (the validation tool that closes "did the lesson actually work?"). Plus a small post-walk-3 punch list and one cosmetic upgrade.

  • Lesson fly-through harness. A new skill at ~/.claude/skills/duo/lesson-flythrough.md that auto-loads on natural-language prompts: "fly through this lesson", "test my new lesson", "preview the lesson", "validate the lesson runs", "smoke-test this playground". The harness pairs duo events --follow --since (cursor-resumable event stream, already shipped) with the new duo html click verb to walk every step of any lesson built on the canonical template — no manual clicking required. Generic: it doesn't know about specific lessons; it walks step events and clicks the next-step button as each step:N-done event fires.
  • duo html click --id <id> | --selector <css>. New canvas-action primitive that synthesizes a click on an iframe element. Read-only op (doesn't generate a recentEdits entry). The element fires its own click handler — which may emit a data-duo-action event, may invoke an in-page handler, or may do nothing. Generalizes to any future "agent walks an interactive page" workflow.
  • Curriculum template at ~/.claude/skills/duo/examples/curriculum-template/. Multi-canvas sibling of the linear lesson-template: orientation.html (launcher with module cards), module-template.html (copy-once-per-module skeleton), lesson-skill/SKILL.md (orchestrator skill skeleton), README. Canonical events follow the lesson:module-<id>-launch / -done / -abandon shape. Used when the next multi-canvas pack lands; today claude-code-basics works as a one-off but is queued for migration.
  • Update banner copy clarifies which version is which (BUG-062). Walk-3 surfaced that "(currently from v0.6.0)" was reading as "Duo itself is at v0.6.0." Rewritten to spell out both versions in the same sentence: "Agent files in ~/.claude/ are from Duo v{installedVersion}. You're running v{appVersion}. Refresh to update."
  • Smoke-walk mid-sentence backtick literals stay inline (BUG-063). Pre-fix, mid-sentence <meta> references in walk manifests were getting pulled out into separate Copy blocks, leaving prose gaps. New isTrailingCmd() helper only pulls cmds out when they're at the end of a sentence; mid-sentence literals stay inline as <code>.
  • Clawd glyph for the new-Claude split-button (ENH-044). The generic + plus glyph in the terminal tab strip's new-Claude half is replaced with a small orange-on-paper monster ("clawd") that's intentionally unmistakable as the "Claude" semantic. Color stays fixed at #c15f3c (Atelier accent family) in both themes.

Why three things in one cut: the harness needed the click verb, the click verb needed the action-vocabulary plumbing, and the curriculum template completes the lesson story. Cutting any one in isolation would have been smaller, less complete. Two design decisions baked in: (1) clicks are primitives, not events — the click verb is intentionally narrow and doesn't simulate hover, key press, or focus (those would each get their own primitive when the use case arises); (2) skill-description recognition replaces ad-hoc CLI verbs — the fly-through is a skill, not a duo lesson fly-through verb. Same logic v0.6.1 applied to "build a lesson." Pattern lock: structured workflows live as skills (auto-loaded by description); CLI verbs are reserved for atomic primitives the agent composes.

v0.6.1 — Canvas authoring vocabulary, sharper 2026-05-02

The follow-up to v0.6.0 that turns "canvas authoring exists" into "canvas authoring is reachable by users who don't yet know what canvas means." Five threads pulled together: the lesson-button bug fix, an enterprise-distro pack toggle, a locked terminology hierarchy, a canonical lesson template, and a skill split tuned for natural-language entry.

  • Vocabulary locked. Canvas = the right pane (slot, type-agnostic). Page = a basic HTML tab inside the canvas. Playground = a page with interactivity (buttons that drive Duo, form inputs, events). Lesson = a playground paired with a guide skill. Start tab = a playground that auto-opens on first launch. The same WorkingTab kind powers both pages and playgrounds — what makes one a playground is whether it has interactivity baked in.
  • Skill split tuned for natural-language entry. The previous one big playground-authoring.md is now three skills: make-page.md (basic HTML), make-playground.md (extends with interactivity — broad description fires on "build a training", "make a guide", "create a lesson", "tutorial for X", "interactive demo", "dashboard with action buttons", anything with a hint of "user clicks, Duo reacts"), lesson-runtime.md (the runtime contract). Plus playground-interaction.md for driving an existing one.
  • Canonical lesson template at ~/.claude/skills/duo/examples/lesson-template/. Copy-and-customize entry point: a playground.html with three stable paint regions (step-counter, step-body, step-controls) and a lesson-skill/SKILL.md with the canonical step-state outline. Replaces "every lesson author invents their own structure" with a shared shape that buys mid-lesson resume + cross-pack consistency.
  • Lesson runtime contract documented. lesson-runtime.md defines canonical event names (lesson:step-N-done, lesson:done, lesson:restart), sidecar state at ~/.claude/duo/lesson-state/<pack>.json (cursor for resume), foreground-vs-subagent watch patterns. The two existing packs (intro-to-duo, claude-code-basics) adopted the canonical event names + paint regions in this cut.
  • claude:spawn data-cmd now lands as Claude's first user message, not a shell command. Pre-fix, the cmd was being typed into zsh, so prose like "Read X and walk me through it" errored. Same fix benefits duo new-tab --claude --cmd "<msg>". This was the silent bug behind v0.6.0's intro-to-duo "Start lesson" appearing to do nothing.
  • Enterprise distro pack toggle. fork.config.json § packs.disabled lists pack directory names this distro opts out of. PackLoader filters at boot; install-service skips at copy time. Forks with their own onboarding suppress intro-to-duo without forking the pack itself. Empty list (default) ships all upstream packs unchanged.

What this means in practice: a future Claude session sees a "build me a training" prompt, loads make-playground automatically (skill description fires), finds the "Lessons specifically" section, copies the template, customizes per-step content, references the runtime contract for event handling. End-to-end clear path. The meta-goal gap from the v0.6.0 zoom-out (user-without-canvas-literacy → working lesson) is closed.

Queued for v0.6.2: ENH-055 (lesson preview / fly-through harness — the canonical packs now give it a stable contract to assert against), ENH-056 (multi-canvas curriculum template — sibling of lesson-template for the claude-code-basics shape).

v0.6.0 — Canvas authoring + lesson packs (the FTUX-tutorial trio lands) 2026-05-02

The three-stage initiative that's been in flight since the v0.5.5 walk lands. Duo now has a complete vocabulary for interactive canvas content (Stage 27), a distro mechanism for skill packs (Stage 18b), and two FTUX lesson packs that auto-open on first launch (Stage 28). All 7 release-blockers from the previous walk attempt are fixed.

  • Six new canvas-action verbs let interactive canvases drive Duo without a Claude session in the loop: editor:open (opens any file with smart routing), nav:reveal (highlights a file in the right navigator pane), selection:set (find/scroll/anchor in editor or canvas), theme:set (light/dark/system), terminal:focus (puts the cursor IN the xterm), duo:event (emits an event that Claude can stream).
  • duo events --follow — new CLI verb that streams a JSON-line event log from any canvas firing duo:event clicks. Cursor format <unix-ms>-<seq>; --since resumes from a snapshot point. Closes issue #19.
  • data-payload-from form binding — a button can read a text input or checkbox value into its event payload. Cross-realm safe (works inside iframe canvases).
  • HTML canvas edit-mode toggle via <meta name="duo-default-editable" content="false">. Mounts the canvas read-only with a discreet "Edit" toggle in the toolbar. Distinct from the older duo-editable hard lock, which now renders a "Read-only · locked" indicator at the top.
  • Five reference templates at ~/.claude/skills/duo/examples/canvas-templates/ — button-card, paint-target, form-input, lesson-scaffold, dashboard. Each is self-contained Atelier styling (works without Duo's stylesheet). Use as starting points for your own canvases.
  • Two FTUX lesson packs — intro-to-duo (a single welcome canvas with a "Start lesson" button that spawns a Claude tab walking you through Duo) and claude-code-basics (a 7-canvas curriculum on Claude Code fundamentals). Both auto-open on first launch from ~/.claude/duo/packs/ via the new pack format. Dismiss them and they don't re-open on subsequent launches.
  • duo packs CLI verb returns the parsed manifests of installed packs + per-pack errors. Useful when you want to audit what's installed or debug why a pack isn't loading.
  • Pinned tabs auto-open on boot. If you pin a tab and quit, that tab returns next launch — even if you closed it before quitting. Matches Chrome / Safari pinned-tab convention. Both browser tabs and file tabs.
  • Send → Duo pill on the browser pane suppressed when no Claude session is live. Was rendering even when there's no Claude tab to send TO. Now gated on window.__duoClaudeLive (set by main when claude-presence flips). Re-test on every release — this one's recurring.
  • Tab right-click context menu fully visible over a browser pane. The browser's WebContentsView used to clip the lower rows of the menu (a native subview compositor issue). Menu now mutes the WCV for the duration. (UX critique noted: the browser pane visibly disappears for the menu — a smoother snapshot-overlay fix is queued as ENH-050.)

Three known issues at this cut: the dev-build update banner reads "currently from v0.6.0" while the running build is the post-cut bump (BUG-062, dev-only); smoke-walk page mid-sentence backtick literals get pulled out into separate Copy blocks leaving prose gaps (BUG-063, smoke-walk-page only); the WCV-mute described above is jarring (ENH-050).

Walk arc that produced this cut: walk-2 surfaced 7 release-blockers → descope to v0.5.6 → fix all 7 → walk-3 caught one v2 follow-up → cut v0.6.0. The discipline that fell out: "internal preview" sections of the changelog mean "code is in the binary but not yet validated." It worked.

v0.5.6 — Stability cut: carry-overs + read-only fix + ⌘W safety 2026-05-02

A focused stability cut that lands the v0.5.5 carry-over fixes alongside the new read-only canvas fix, the ⌘W data-loss patch, and the smoke-walk page Copy buttons. Stages 27 / 18b / 28 (canvas-authoring vocabulary, distro skill packs, lesson packs) ride along as initial preview but are not yet validated — full release lands in v0.6.0 once their walk-2 regressions are fixed.

  • Send → Duo pill on the browser pane is now visible AND clickable. The pill renders inside the page itself (via Chrome DevTools Protocol injection) instead of in renderer DOM where the macOS native subview compositor was occluding it. Selection snapshot is captured synchronously at click-time so the round-trip can't race.
  • Read-only canvas toggle now actually reverts. Off → on → off was leaving the body editable; the wiring effect added edit-mode attributes but never removed them on flip-back. Fixed by an explicit revert branch.
  • ⌘W only closes tabs — never the window. The "Close Window" menu accelerator moved to ⌘⇧W (Chrome's convention). No more accidentally closing the entire Duo window when reaching for ⌘W to close a tab.
  • "Move to Trash" confirm dialog reads coherently — was sandwiching the trash copy between hardcoded "Close pinned tab?" / "is pinned. Close it anyway?" strings.
  • Right-click on a markdown editor tab shows the full context menu — the menu was being clipped by the strip's overflow stacking context. Portaled to document.body now.
  • FAQ entry for the conda LC_ALL=C terminal-locale gotcha. Multi-byte Unicode chars come out garbled when you paste into a terminal whose shell has a non-UTF-8 locale. duo doctor now flags this; the FAQ explains the fix recipe.
  • HTML canvas no longer auto-prompts to inject IDs on every fresh open — gated behind a feature flag (off by default). Existing files with IDs continue to work; agents can still call duo html stamp-ids manually.
  • Smoke-walk page Copy buttons — any backtick-wrapped command in a smoke-walk step now renders as a code block with a one-click Copy button. Replaces triple-click + careful selection of inline code.

Three known issues — targeted for v0.6.0: the Send → Duo pill in the browser pane fires even without an active Claude session (BUG-056); pinned working-pane tabs are lost across sessions / app upgrades (BUG-057); and the WorkingTabStrip context menu is still occluded by the browser pane in the lower portion of the menu (BUG-058 — needs a different fix path than BUG-050's portal).

Why this is v0.5.6 and not v0.6.0. The original v0.6.0 plan was Stages 27 + 18b + 28 landing together. Walk-2 of v0.6.0 surfaced 7 release-blockers in those features; descoping to a smaller v0.5.6 here gets the FIXED-and-VERIFIED work to users now and lets 27/28 graduate to shipped status separately when they pass walk-3.

v0.5.4 — Right-click everywhere + ⌘\` finally clean 2026-05-01

A tight follow-up sprint to v0.5.3 — pulling the carry-over Known Issues from that cut and shipping six of seven cleanly. Every right-click in Duo now does what users expect, ⌘\` after duo open finally toggles back to the terminal cleanly, and a few smaller paper-cuts cleared.

  • Right-click context menus everywhere. Cut / Copy / Paste / Select All / Look Up / Spell-check / Inspect (in dev) in the markdown editor, HTML canvas, and browser pane — previously a no-op. Wired via the electron-context-menu library, attached per-webContents so every browser tab gets it too.
  • "Copy as Plain Text" — new entry at the top of the right-click menu when you have text selected, plus ⌘⌥C in the Edit menu. Strips formatting marks; pastes cleanly into terminals and other plain-text targets.
  • ⌘F find-in-page in the browser pane. Parity with the markdown editor's find — find bar above the address row, ⌘G / ⌘⇧F navigate matches, ⎋ closes, match counts stream live as you type.
  • ⌘\` after duo open toggles back cleanly. Third try — the previous two rounds chased the wrong cause. Real fix: stop the menu accelerator's focus reclaim from racing the toggle's read of the current pane.
  • Cycling between markdown tabs is instant. File-tab editors stay mounted across switches now (display-toggled) — no more 1–2s rebuild per ⌃Tab.
  • Navigator breadcrumb shows the active folder. Default scroll position is now flush with the right edge instead of the left, so deep paths show the current folder by default. Last segment is rendered bolder so the eye lands on it.
  • Build-version badge in the titlebar. Glanceable confirmation of which version is running — useful when validating fixes against a dev build. Shows ·dev in accent color when not packaged.
  • Skill: troubleshooting for "duo: command not found". If your shell can't find duo on $PATH, the skill now walks the agent through checking the install locations and using the binary by full path — instead of giving up and falling back to native macOS open, which doesn't route through Duo.

One known issue, parked indefinitely. duo doc goto --heading X still picks a wrong-but-near heading on very large docs (tasks.md). The v3 → v4 → v5 fix attempts are in the codebase with diagnostic instrumentation, but the bug doesn't block usable behavior for most cases (line-based and anchor-based goto work fine). Carries over to a future debugging pass.

Terminal paste rendering quirk. If multi-byte Unicode characters (em-dash, ⌘⌥, etc.) come out as raw bytes when you paste into a terminal, your shell's locale is non-UTF-8 (often from conda's (base) activator setting LC_ALL=C). Fix: export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 in your ~/.zshrc after conda init. Not a Duo bug — TextEdit confirms the clipboard is correct.

v0.5.3 — Two stages closed + a polish sweep 2026-05-01

Two roadmap stages flipped to ✅ in one cut: Stage 12 (Atelier visual redesign) closes with the whisper-level agent presence — a soft accent dot in the titlebar that breathes when Claude is running, and a brief halo on the working pane when Claude reads your selection. Stage 15 (Send → Duo) closes with the polish trio that's been deferred since 15.1 + 15.2 shipped.

  • ⌘D fires Send → Duo on whichever surface (markdown editor, canvas, browser pane) currently has a selection. No more reaching for the floating pill — the chord works from anywhere.
  • Long selections truncate at 5000 chars with a marker that tells the agent how to fetch the rest. Stops a runaway 50k-char blockquote from flooding your terminal scrollback.
  • Canvas selections with images now flatten cleanly. An <img> tag in the selected range becomes [image: alt-text] placeholder text — the agent knows an image was there without the payload turning into a base64 wall.
  • ⌘F find-in-document for the markdown editor — find bar with match counter, ↓/↑ + ▼/▲ navigation, smooth scroll-to-match. Works in dark mode now too (the input was unreadable before).
  • ⌘[ / ⌘] outdent / indent in markdown lists (bullet, ordered, and task lists).
  • Three new agent CLI verbs. duo doc goto --heading "X" / --line N / --anchor "Y" jumps the active editor to a heading, line, or GitHub-slug anchor. duo doc find "Q" does a read-only buffer search. duo reload reloads the active browser tab without needing a URL — pair for duo navigate in the agent's iteration loop.
  • Right-click context menus on the file tree's whitespace (project-root scoped: New file / New folder / Open terminal here / Reveal in Finder) and on WorkingPane tabs (file tabs and file:// browser tabs alike: Reveal in navigator / Rename… / Pin tab / Move to Trash…). The right-click on browser tabs uses a temporary WebContentsView mute trick to dodge a macOS native subview occlusion that was clipping the menu.
  • Tab strip pans to keep the active tab visible when you have more tabs open than fit on screen — across both the terminal pane and the working pane.
  • ⌃Tab cycle reaches all working-pane tabs. Markdown editor and HTML canvas tabs were invisible to the cycle (it only knew about browser tabs); now the cycle iterates the merged file + browser list. Long-running recurring bug, fifth instance, finally root-caused.
  • Editable breadcrumb in the navigator — ⌘⇧G flips it into a path-input. Type or paste a path; Return navigates.
  • Session restore drops files that no longer exist — no more "phantom" tabs pointing at deleted files.
  • Off-host blocklist routes more aggressively. Sites in external-domains.json route to your system browser even on user-driven navigation (typed URL, clicked link, popup) — previously only the duo CLI did the routing.
  • The Files-pane collapse button is visible at rest now — was barely-visible muted-zinc on cream paper, swapped to a Finder/VS-Code-style sidebar-toggle glyph.
  • Bullet markers round-trip. Type * , - , or + at line start; the marker survives save/load (was always coercing to one default before).
  • New smoke-walk skill. The end-of-sprint verification flow now generates an interactive HTML walk page with one entry per shipped item — pass/fail toggle, notes textarea, and a Copy results button that dumps a structured block for paste-back into the agent. v0.5.3 itself shipped through three smoke walks.

One known issue, intentionally shipped. duo doc goto --heading X still picks the wrong heading on very large docs (tasks.md). v2 fixed the scroll plumbing; v3 tightened match precedence but a wrong heading still wins. Likely buffer staleness (Stage 16 isn't shipped yet) or a regex permissivity in TipTap's heading walk. Released as-is per owner call; the response shape now exposes a matched_heading field so v4 debugging is self-diagnosing.

v0.5.2 — Bug-smashing sprint 2026-04-29

Six fixes and one small new capability — all on the surfaces you touch most. No new headline feature, just a chunk of papercuts gone in one day.

  • Pane-size shortcuts — View → Pane size submenu with five presets (Even, Terminal heavy, Canvas heavy, Full terminal, Full canvas). Or hit ⌘⌥1 / ⌘⌥2 / ⌘⌥3 for terminal-heavy / 50-50 / canvas-heavy, ⌘⌥0 for full terminal, ⌘⌥9 for full canvas. From a Duo terminal: duo split 67 (or duo split even, etc.).
  • The split divider works over canvases now. Dragging the divider rightward used to stall as soon as the cursor crossed into the HTML canvas. Fixed — it follows your cursor smoothly in either direction.
  • Canvases stop stealing focus from your terminal mid-typing. If you opened a canvas, then clicked into a terminal, then typed — the cursor used to occasionally jump back into the canvas mid-keystroke (any time the canvas re-mounted). Now it only takes focus when you actually have the working pane focused.
  • Autosave pauses while you're deciding on an agent edit. When the agent's "Claude wants to edit this document" banner appears, your editor's autosave timer is suspended until you accept or decline. Closes a race where the autosave could fire mid-banner with stale content.
  • Replace-all warning is more explicit. When the agent wants to replace your whole document, the banner now reads "Replace the whole document (your unsaved edits will be lost)" — so you can decline deliberately rather than accept on muscle memory.
  • Populated canvases no longer have an onboarding card floating over them. The "Markdown shortcuts work as you type / Component blocks / Templates / Ask the agent" card was showing on every canvas open, including ones you'd already filled with content. Disabled until we rebuild it correctly.
  • "Couldn't find Claude Code" banner now only fires when Claude Code actually isn't installed. If you have a slow shell startup (NVM, conda, oh-my-zsh, etc.), the resolver used to time out and falsely report Claude as missing. Now we check well-known install locations directly first; the shell fallback only fires if those miss, and has 15s headroom instead of 5s.
  • "Add to PATH" button in the install banner. If ~/.local/bin isn't on your shell's PATH (so duo doesn't work from external Terminal/iTerm sessions), one click appends a fenced export PATH block to your ~/.zshrc (or ~/.bash_profile / ~/.config/fish/config.fish). Idempotent — re-runs detect the fence and skip.

v0.5.0 — Navigator polish + fork-friendly architecture 2026-04-27

The first MINOR release since v0.4.0. Big things changed in the file navigator on the left, and Duo can now be forked by editing one config file (mostly relevant to teams running their own internal Duo build).

  • Navigator works like Finder / VS Code now. Single-click on a file or folder selects it (highlights without opening). Double-click opens the file in the right pane, or navigates the tree into the folder. The little arrow next to a folder is its own thing — clicking it just expands or collapses, no longer also selects.

v0.4.4 — DMG launch fix 2026-04-27

One-line hotfix for a release-blocker: every DMG cut from v0.4.0 through v0.4.3 was crashing on launch with Cannot find module 'node-pty'. The build was excluding all production node_modules from the bundle by accident, so Duo's main process couldn't start. v0.4.4 includes them properly.   • The fix. electron-builder.yml's files config replaced a catch-all "!node_modules/**/*" exclusion with a positive node_modules/**/* include. electron-builder's smart filter still keeps dev deps out, so the bundle stays lean — the only change is that runtime modules node-pty, chokidar, and electron-updater now actually ship.

Earlier "successful" runs were either npm run dev (which loads node-pty from the local repo) or installs that inherited node-pty on disk from a previous, differently-built bundle.

The cut-version skill grew a mandatory launch-smoke validation step (scripts/validate-dmg-launch.sh): mounts the DMG, confirms required runtime modules are reachable in either the asar or unpacked tree, then opens the .app and verifies the main process is alive past 8 seconds. v0.4.1 — sandbox resilience 2026-04-27

Closes the silent-failure mode where every duo command died inside a sandboxed Claude Code session. The CLI tries the Unix socket first; on EPERM / ECONNREFUSED / connect-timeout it falls through to TCP, sending the token as the first NDJSON handshake line. Prints a clear "Claude Code sandbox detected (Unix socket blocked) — using TCP fallback" line when that's the cause, with a copy-paste .claude/settings.local.json allowlist if you want the faster Unix-socket path back. First move on any unrecognized duo failure.
  • Sandbox-writable install path (Stage 20). duo install now prefers ~/.claude/bin/duo over /usr/local/bin/duo — the ~/.claude/ tree is writable from inside a sandboxed Claude Code PTY, so re-installing keeps working without sudo. --system opts back into the legacy path. Getting started

How do I install Duo?

v0.1.0 is pre-distribution. To run it: clone the repo, npm install, then either npm run dev for the live build or npm run dist to produce an unsigned macOS DMG. First-launch self-install (auto-installing the duo CLI and the skill / subagent into ~/.claude/) ships in v0.2.0.

The terminal says "claude not found" — how do I fix that?

Duo expects the claude binary on your PATH (Claude Code CLI). Install it via npm install -g @anthropic-ai/claude-code or whatever the current install instruction is for your environment. Duo re-checks which claude on every new tab spawn, so a fresh terminal will pick up the installed binary.

How do I run duo commands from Claude or my own scripts?

The duo binary lives at cli/duo in the repo. For dev use, either invoke it directly (./cli/duo help) or symlink it onto your PATH (ln -s "$(pwd)/cli/duo" /usr/local/bin/duo). The Stage 18 first-launch installer will do this automatically when distribution begins.

Note: duo talks to Duo's main process over a Unix socket. It only works when Duo is running.

Using Duo

How do I open or create a markdown file?

Click any .md file in the file navigator (left column) to open it as the rich editor. To create a new one: click + on the working-pane tab strip, type a filename ending in .md, and hit Enter.

How does the HTML canvas work?

Open any .html file from the navigator and it renders as a live, editable canvas — what you see is what gets saved. The same toolbar as the markdown editor (heading picker, lists, tables, etc.) plus markdown shortcuts on typing. Comments live in a sidecar (<file>.html.duo.json) and never mix into the saved HTML. Claude can edit the canvas structurally via duo html * commands.

What is the "Send → Duo" pill?

When you select text in the markdown editor, the browser pane, or the HTML canvas, a small "Send → Duo" pill appears beside the selection. Click it; the selection lands in your active terminal as a formatted quote with provenance (path / URL trail) so Claude knows where it came from. Three formats available via duo selection-format a|b|c.

What's the difference between + and > on the terminal tab strip?

+ opens a Claude Code session in a new tab (auto-launches claude). > opens a vanilla shell. Keyboard equivalents: ⌘T always opens a new browser tab (Chrome parity), ⌘⇧T opens a Claude tab from anywhere.

Why did clicking a link send me to my default browser?

Off-host URLs go to your default browser via shell.openExternal — the assumption being that work-restricted sites (SSO, internal pages, bookmarked tools) live on your real browser, not Duo's embedded Chromium. Domains on the external-domains list get this treatment automatically. Add or remove domains by editing ~/.claude/duo/external-domains.json.

How do I switch between light and dark themes?

The theme button is in the title bar (top-right). Click "System" / "Light" / "Dark" to cycle. From the CLI: duo theme system|light|dark.

For Claude / agent users

How do I ask Claude what Duo can do?

The What Duo does page lists every capability with a use case and the CLI invocation. From a Duo terminal, duo help dumps the full verb reference. Claude knows about both — just describe what you want and let it pick the right tool.

What is the Duo subagent?

A specialized Haiku-powered agent that handles mechanical Duo work (find this element, summarize the selection, route a quote to a terminal). Triggered automatically by Claude Code when the task fits — keeps Sonnet's working memory free for the actual problem you're solving.

How does Claude know it's running inside Duo?

Every PTY Duo spawns gets DUO_SESSION, DUO_SOCKET, DUO_VERSION, and TERM_PROGRAM=Duo in its environment. Tools branch on these. To check from a terminal: echo $DUO_SESSION — if it's non-empty, you're inside Duo.

Troubleshooting

Why does duo silently fail in some Claude Code sessions?

Claude Code runs each Bash tool call inside a macOS Seatbelt sandbox that gates Unix-domain-socket connections. Duo's bridge is a Unix socket — so duo commands invoked from a sandboxed Claude Code session can hang or return ECONNREFUSED. Workaround: invoke duo from a Duo-spawned terminal directly (those PTYs aren't sandboxed). The sandbox-tolerant transport ADR (in docs/DECISIONS.md) tracks the long-term fix.

Why doesn't ⌘T open a Claude tab when I'm in a terminal?

It used to (Stage 19c spec) but no longer does (BUG-008 spec resolution, 2026-04-26). ⌘T is now always a new browser tab regardless of focus — Chrome parity. To open a Claude tab from the keyboard, use ⌘⇧T. To open one from the UI, click + on the terminal tab strip.

The xterm-eats-keystroke issue that caused BUG-008 was also fixed in the same ship: every Duo-global keyboard shortcut now reaches its handler from terminal focus.

I clicked + for a Claude tab and the prompt is just showing "claude" without running.

Known issue (tasks.md § BUG-009). The auto-launch wiring writes claude\n too early — before the shell prompt is ready — so the newline gets dropped. Workaround: press Enter manually. Fix lands in v0.2.0.

What does the welcome banner install?

One click copies four things into your home directory:

  • ~/.claude/skills/duo/ — the Duo skill (so any Claude Code session in any directory discovers Duo's CLI).
  • ~/.claude/agents/duo.md — the Duo subagent (Haiku 4.5; specialized for mechanical Duo work).
  • ~/.claude/duo/help/ — local copies of FAQ + What Duo does (so you can customize them; the bundle copies still serve as fallback).
  • ~/.local/bin/duo — the duo CLI binary.

Plus a provenance file at ~/.claude/duo/installed.json with the version + timestamp. Idempotent — re-running on an upgrade overwrites everything and re-stamps the version. ~/.claude/duo/external-domains.json is bootstrapped if absent and never clobbered (it can hold your own customizations).

The banner says my $PATH is missing ~/.local/bin — what do I do?

Add this line to your ~/.zshrc (or ~/.bashrc if you use bash):

export PATH="$HOME/.local/bin:$PATH"

Then open a fresh terminal (or run source ~/.zshrc in an existing one). duo help should now work.

You don't need this for Duo's UI to work — only for invoking duo from arbitrary terminals (including Claude Code sessions running outside Duo).

Why do special characters look broken when I paste into the terminal?

Multi-byte Unicode characters (em-dash, ⌘⌥, ñ, emoji, etc.) come out as raw bytes when your shell's locale isn't UTF-8. Most common cause: conda's (base) activator sets LC_ALL=C, which strips UTF-8 awareness from anything that runs after it.

Quick check from any terminal:

locale | grep -E 'LC_ALL|LC_CTYPE|LANG'

If you see C or POSIX in any of those, fix it by adding this to your ~/.zshrc (or ~/.bashrc) — after the conda conda init block, not before:

export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8

Open a fresh terminal. The locale gotcha affects every terminal paste on your machine, not just Duo's — TextEdit and other GUI apps round-trip multi-byte characters fine because they don't go through a shell.
