What's new

v0.4.1 — sandbox resilience 2026-04-27

Closes the silent-failure mode where every duo command died inside a sandboxed Claude Code session. Capital One (and other enterprise) Claude Code installs run with default Seatbelt policy, which blocks Unix-domain sockets — and Duo's whole agent-side bridge ran on one. Three pieces moved: a TCP fallback transport alongside the Unix socket, a new duo doctor verb that names the failure mode instead of leaving you guessing, and a sandbox-writable default install path.

  • TCP fallback transport (Stage 20). Electron now dual-listens on the Unix socket (primary, fast) and an ephemeral 127.0.0.1 TCP port with a per-launch random auth token at ~/Library/Application Support/duo/duo.port. The CLI tries the Unix socket first; on EPERM / ECONNREFUSED / connect-timeout it falls through to TCP, sending the token as the first NDJSON handshake line. Non-sandboxed sessions never notice; sandboxed sessions Just Work.
  • duo doctor diagnostic (Stage 20). New verb. Probes both transports, reports app/CLI version match, $DUO_SESSION presence, install-path discovery, and skill/agent-file presence. Prints a clear "Claude Code sandbox detected (Unix socket blocked) — using TCP fallback" line when that's the cause, with a copy-paste .claude/settings.local.json allowlist if you want the faster Unix-socket path back. First move on any unrecognized duo failure.
  • Sandbox-writable install path (Stage 20). duo install now prefers ~/.claude/bin/duo over /usr/local/bin/duo — the ~/.claude/ tree is writable from inside a sandboxed Claude Code PTY, so re-installing keeps working without sudo. --system opts back into the legacy path. The command prints a one-line export PATH=... hint if the chosen target isn't already on your PATH.
  • duo wait --timeout race fixed. duo wait --timeout 30000 no longer hits the 10s socket cap and dies with a misleading "Timeout waiting for response" while the renderer is still polling. Socket cap is now max(explicit + 5s buffer, default).

Known issues at this version: DMG remains unsigned — Gatekeeper warns on first launch (Stage 21 signing + notarization is in flight on a parallel branch with an Electron 24→26 upgrade). The rest of the Stage 20 cluster is still ⬜: tab numbers in the unified strip, terminal selection refinements, duo reload, pane-aware ⌘+/- zoom (issues #22 / #23), PTY-side sandbox audit (issue #12). TCP fallback was smoke-tested via DUO_TCP_ONLY=1; first real-sandbox confirmation comes from your next Capital One Claude Code session.

v0.4.0 — context pedagogy 2026-04-26

The file navigator splits into two panes that teach you, at a glance, that Claude reads context from BOTH user-level and project-level buckets. Plus four supporting features: real GitHub-Releases update banner, post-redirect "Sent <host> to your default browser" chrome banner, *.capitalone.com defaulted in the off-host list, Edit-menu surface for ⌘⇧V paste-as-plain-text, and Stage 21 signing-script prep.

  • Navigator dual-pane overhaul (Stage 22). Top pane "Your Claude settings" shows the curated three at ~/.claude/ (CLAUDE.md, skills/, agents/) with a "Show all" toggle for the rest. Bottom pane is the existing project tree with a new "Project Claude context" group above the regular file list (surfaces ./CLAUDE.md / ./.claude/ / ./tasks.md / ./AGENTS.md when they exist). The visual separation IS the pedagogy: see at a glance that the agent reads from both buckets, no dotfile knowledge required.
  • GitHub Releases auto-update banner. A new banner above the WorkingPane queries api.github.com and surfaces "Duo vX.Y.Z is available" with a one-click link to the release page. Distinct from the existing "re-run install" banner (which fires when your installed.json drifts from the running app). Per-version dismissal: skipping v0.4.0 stays quiet until v0.4.1 ships.
  • Post-redirect chrome banner (Stage 25). After duo external <url> succeeds, a small banner appears above the WorkingPane: "Sent <host> to your default browser. ⌘Tab to find it." Auto-dismisses after 6s. Optional per-domain "reason" text from external-domains.json's extended schema (entries can now be either a string or {host, reason?}).
  • *.capitalone.com default in external-domains.json. Install bootstrap seeds the file with Cap One on the off-host list so Trailblazers' Cap One web surfaces (which need the corporate-managed browser for SSO + internal CDN certs) auto-route to the system browser without manual config. Existing files are never clobbered.
  • Edit menu "Paste and Match Style". Native macOS-standard menu item with ⌘⇧V accelerator. The keyboard chord already worked in both editors since v0.3.1; this adds the menu surface for discoverability.
  • Stage 21 signing-script prep. scripts/dist-signed.sh + scripts/validate-signed-dmg.sh handle the signed + notarized cut path (sources cert env vars from ~/Documents/duo-private/.env, runs npm run dist, validates with codesign + spctl + stapler). v0.4.0 itself ships unsigned; the signed cut runs next time the keychain prompt can be answered in real-time.

Known issues at this version: DMG is unsigned — Gatekeeper warns on first launch (Stage 21). Markdown editor still has no comment support (MISSING-001 — Stage 14a, queued for v0.5.0). Browser tabs don't auto-restore across launches (Stage 21c). Browser-pane Send→Duo pill is still invisible behind the WebContentsView (BUG-006 — needs design decision).

v0.3.1 — cleanup sprint 2026-04-26

Eight items in one release: three regressions fixed, three enhancements paired cleanly, two filed-but-stalled bugs from prior cycles closed. No big architectural strokes — the housekeeping after v0.3.0's surface area expansion.

  • New HTML canvases ship with IDs + Atelier defaults (ENH-001 + ENH-004). duo html new and ⌘N + .html stamp data-duo-id ULIDs on body/h1/p at write time AND embed an inline stylesheet (cream paper, ink-soft body, serif headings, body width cap, dark-mode media query, viewport meta). The first-open "Add stable IDs?" prompt is now skipped for Duo-authored canvases. Styles are local + editable — delete or rewrite freely.
  • Paste as plain text (ENH-002). ⌘⇧V in both editors reads text/plain and inserts without HTML formatting. macOS "Paste and Match Style" parity.
  • Dark-mode pasted-bold contrast fixed (BUG-016). Regular ⌘V in the canvas now scrubs inline style="color:…" / style="background:…" and class attributes from pasted HTML, so pasted nodes inherit the canvas's own ink token instead of the source's brown-on-brown. Other inline styles (margins, font-size) are kept.
  • Theme "system" mode follows macOS again (BUG-017). Was hardcoded at the boot to 'light' which leaked into the renderer's prefers-color-scheme query. Now syncs nativeTheme.themeSource with the user's mode push.
  • Deleted files no longer linger in the navigator (BUG-007). The chokidar unlink events were firing correctly all along; the renderer just wasn't subscribed. useNavigator now installs a watcher and refreshes the parent directory on add/change/remove. External rm, agent writes, Finder operations all reflect within a frame.
  • Default-pinned help tabs (ENH-003). Install now bootstraps ~/.claude/duo/pins.json with FAQ + "What Duo Does" pre-pinned. The browser-pane default landing prefers the user-installed help copy at ~/.claude/duo/help/, so when you open either tab it renders with the pin glyph + sorts to leftmost.
  • duo key End --modifiers cmd stops triggering the About panel (BUG-005). CLI now silently translates cross-platform navigation combos to Mac equivalents (Cmd+End → Cmd+ArrowDown, Cmd+Home → Cmd+ArrowUp, Cmd+PageDown/Up drops Cmd). 9/9 cases pass; non-macOS unaffected.
  • HTML canvas comment rail no longer renders an empty column (BUG-015). Gated on railThreads.length > 0; reappears when the first comment lands.

Known issues at this version: Markdown editor still has no comment support (MISSING-001 — Stage 14a, queued for v0.4.0). DMG is unsigned (Stage 21 still). Browser tabs don't auto-restore across launches (Stage 21c).

v0.3.0 — Duo-aware Claude 2026-04-26

Every claude session inside Duo now arrives Duo-aware — the agent already knows it's in Duo and which duo verbs to prefer, without the user typing anything. Canvas pages can drive the workspace via data-duo-action buttons. Keyboard shortcuts now work in every pane by construction (no more "TipTap / canvas swallowed it" regressions). DMG can be downloaded directly from GitHub Releases.

  • Passive priming (Stage 19b). Two delivery mechanisms: a load-bearing ~/.claude/duo/bin/claude shim (PATH-prepended on every Duo PTY) wraps the real binary with --append-system-prompt "$(cat ~/.claude/duo/priming.md)" when $DUO_SESSION is set; a redundant SessionStart hook in ~/.claude/settings.json backs it up. The bundled priming.md ships with Duo and is user-editable in ~/.claude/duo/priming.md.
  • Canvas actions (Stage 23). 3-verb vocabulary: data-duo-action="claude:spawn" opens a new Claude tab, terminal:send writes to the active PTY (with optional data-enter="true"), browser:open navigates a new browser tab. Trust gate v1: actions fire only on canvases under ~/.claude/duo/. Try the worked example: open ~/.claude/duo/help/canvas-actions-demo.html from your file tree.
  • Preventative kb-shortcut architecture. Every interactive surface (xterm, browser webview, iframe, TipTap) now consults a single shared matcher (renderer/keyboard/globalShortcuts.ts) and yields global shortcuts to a capture-phase document listener. Adding a new shortcut covers every surface; adding a new pane that adopts one of the three documented patterns inherits every shortcut. Closes BUG-012/013/014 by construction (canvas + markdown editor were swallowing ⌘T / ⌃Tab / ⌘N).
  • duo send --enter flag. Pairs with the canvas data-enter="true" attribute to submit the payload on the user's behalf instead of waiting for confirmation.
  • GitHub Releases DMG distribution. Latest unsigned DMG now downloadable from github.com/dudgeon/duo/releases/latest. The README points at releases/latest/download/Duo-<v>-arm64.dmg (Apple Silicon) and Duo-<v>.dmg (Intel).
  • BUG-010 closed. The cosmetic claude echo above the shell prompt in new Claude tabs is gone — waitForPtyReady now matches a prompt-tail regex on the (ANSI-stripped) buffered output instead of resolving on the first PTY data event.

Known issues at this version: Canvas comment rail renders even with no comments (BUG-015). Pasted bold text in dark-mode canvas is low-contrast (BUG-016). Theme "system" mode appears to render as light regardless of OS preference (BUG-017). Markdown editor still has no comment support (MISSING-001 — Stage 14a). New canvas files trigger the "Add stable IDs?" prompt even though Duo wrote them (ENH-001). No "Paste and Match Style" yet (ENH-002). All filed in tasks.md for v0.3.1.

v0.2.0 — FTUX foundation 2026-04-26

The first release a fresh user can install in one click. Welcome banner installs the skill, subagent, help files, and the duo CLI binary in one click. New default browser landing is this FAQ instead of about:blank. WorkingPane tabs are pinnable. Two keyboard-routing bugs fixed (⌘T, + → claude).

  • One-click install (Stage 18). Welcome banner copies skill/ + agents/duo.md + help/*.html into ~/.claude/ and cli/duo into ~/.local/bin/duo. If ~/.local/bin isn't on your $PATH, the banner shows the one-liner to add to your shell rc.
  • Pin tabs (Stage 24). Right-click any working-pane tab → "Pin tab." Pinned tabs render with a pin glyph, sort to leftmost, and gate ⌘W behind a confirm modal. Pin survives Duo restarts.
  • FAQ + What Duo Does as the default landing. New browser tabs land on help/faq.html instead of about:blank. Two new <meta> conventions on HTML files: duo-open-in routes to the browser pane vs the canvas, duo-editable=false mounts read-only.
  • Keyboard fixes. ⌘T from terminal focus now opens a new browser tab (Chrome parity); ⌘⇧T opens a Claude tab. Whole family of "xterm eats this Duo shortcut" bugs swept in one pass.
  • Bug fix. The + button on the terminal strip now reliably auto-launches Claude (was racing the shell startup).

Known issues at this version: A bare claude still echoes above the prompt in new claude tabs (cosmetic; claude DOES launch — see tasks.md § BUG-010). The DMG is unsigned (Gatekeeper warns on first launch); Stage 21 closes that.

v0.1.0 — the foundation 2026-04-26

The first labelled version of Duo. Everything that's shipped to date is now versioned and trackable. From here forward, each release adds an entry to this section.

  • Three-pane workspace: file navigator, terminal pane (with claude / shell split-button), polymorphic working pane (browser, markdown editor, HTML canvas).
  • Shared formatting toolbar across markdown editor and HTML canvas; markdown shortcuts on typing.
  • Full HTML canvas: edit live, comment threads in a sidecar, agent CLI ops (duo html new/query/get/set/replace/append/remove/attr/comment/comments).

Getting started

How do I install Duo?

v0.1.0 is pre-distribution. To run it: clone the repo, npm install, then either npm run dev for the live build or npm run dist to produce an unsigned macOS DMG. First-launch self-install (auto-installing the duo CLI and the skill / subagent into ~/.claude/) ships in v0.2.0.

The terminal says "claude not found" — how do I fix that?

Duo expects the claude binary on your PATH (Claude Code CLI). Install it via npm install -g @anthropic-ai/claude-code or whatever the current install instruction is for your environment. Duo re-checks which claude on every new tab spawn, so a fresh terminal will pick up the installed binary.

How do I run duo commands from Claude or my own scripts?

The duo binary lives at cli/duo in the repo. For dev use, either invoke it directly (./cli/duo help) or symlink it onto your PATH (ln -s "$(pwd)/cli/duo" /usr/local/bin/duo). The Stage 18 first-launch installer will do this automatically when distribution begins.

Note: duo talks to Duo's main process over a Unix socket. It only works when Duo is running.

Using Duo

How do I open or create a markdown file?

Click any .md file in the file navigator (left column) to open it as the rich editor. To create a new one: click + on the working-pane tab strip, type a filename ending in .md, and hit Enter.

How does the HTML canvas work?

Open any .html file from the navigator and it renders as a live, editable canvas — what you see is what gets saved. The same toolbar as the markdown editor (heading picker, lists, tables, etc.) plus markdown shortcuts on typing. Comments live in a sidecar (<file>.html.duo.json) and never mix into the saved HTML. Claude can edit the canvas structurally via duo html * commands.

What is the "Send → Duo" pill?

When you select text in the markdown editor, the browser pane, or the HTML canvas, a small "Send → Duo" pill appears beside the selection. Click it; the selection lands in your active terminal as a formatted quote with provenance (path / URL trail) so Claude knows where it came from. Three formats available via duo selection-format a|b|c.

What's the difference between + and > on the terminal tab strip?

+ opens a Claude Code session in a new tab (auto-launches claude). > opens a vanilla shell. Keyboard equivalents: ⌘T always opens a new browser tab (Chrome parity), ⌘⇧T opens a Claude tab from anywhere.

Why did clicking a link send me to my default browser?

Off-host URLs go to your default browser via shell.openExternal — the assumption being that work-restricted sites (SSO, internal pages, bookmarked tools) live on your real browser, not Duo's embedded Chromium. Domains on the external-domains list get this treatment automatically. Add or remove domains by editing ~/.claude/duo/external-domains.json.

How do I switch between light and dark themes?

The theme button is in the title bar (top-right). Click "System" / "Light" / "Dark" to cycle. From the CLI: duo theme system|light|dark.

For Claude / agent users

How do I ask Claude what Duo can do?

The What Duo does page lists every capability with a use case and the CLI invocation. From a Duo terminal, duo help dumps the full verb reference. Claude knows about both — just describe what you want and let it pick the right tool.

What is the Duo subagent?

A specialized Haiku-powered agent that handles mechanical Duo work (find this element, summarize the selection, route a quote to a terminal). Triggered automatically by Claude Code when the task fits — keeps Sonnet's working memory free for the actual problem you're solving.

How does Claude know it's running inside Duo?

Every PTY Duo spawns gets DUO_SESSION, DUO_SOCKET, DUO_VERSION, and TERM_PROGRAM=Duo in its environment. Tools branch on these. To check from a terminal: echo $DUO_SESSION — if it's non-empty, you're inside Duo.

Troubleshooting

Why does duo silently fail in some Claude Code sessions?

Claude Code runs each Bash tool call inside a macOS Seatbelt sandbox that gates Unix-domain-socket connections. Duo's bridge is a Unix socket — so duo commands invoked from a sandboxed Claude Code session can hang or return ECONNREFUSED. Workaround: invoke duo from a Duo-spawned terminal directly (those PTYs aren't sandboxed). The sandbox-tolerant transport ADR (in docs/DECISIONS.md) tracks the long-term fix.

Why doesn't ⌘T open a Claude tab when I'm in a terminal?

It used to (Stage 19c spec) but no longer does (BUG-008 spec resolution, 2026-04-26). ⌘T is now always a new browser tab regardless of focus — Chrome parity. To open a Claude tab from the keyboard, use ⌘⇧T. To open one from the UI, click + on the terminal tab strip.

The xterm-eats-keystroke issue that caused BUG-008 was also fixed in the same ship: every Duo-global keyboard shortcut now reaches its handler from terminal focus.

I clicked + for a Claude tab and the prompt is just showing "claude" without running.

Known issue (tasks.md § BUG-009). The auto-launch wiring writes claude\n too early — before the shell prompt is ready — so the newline gets dropped. Workaround: press Enter manually. Fix lands in v0.2.0.

What does the welcome banner install?

One click copies four things into your home directory:

  • ~/.claude/skills/duo/ — the Duo skill (so any Claude Code session in any directory discovers Duo's CLI).
  • ~/.claude/agents/duo.md — the Duo subagent (Haiku 4.5; specialized for mechanical Duo work).
  • ~/.claude/duo/help/ — local copies of FAQ + What Duo does (so you can customize them; the bundle copies still serve as fallback).
  • ~/.local/bin/duo — the duo CLI binary.

Plus a provenance file at ~/.claude/duo/installed.json with the version + timestamp. Idempotent — re-running on an upgrade overwrites everything and re-stamps the version. ~/.claude/duo/external-domains.json is bootstrapped if absent and never clobbered (it can hold your own customizations).

The banner says my $PATH is missing ~/.local/bin — what do I do?

Add this line to your ~/.zshrc (or ~/.bashrc if you use bash):

export PATH="$HOME/.local/bin:$PATH"

Then open a fresh terminal (or run source ~/.zshrc in an existing one). duo help should now work.

You don't need this for Duo's UI to work — only for invoking duo from arbitrary terminals (including Claude Code sessions running outside Duo).
