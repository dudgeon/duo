What's new

v0.1.0 — the foundation 2026-04-26

The first labelled version of Duo. Everything that's shipped to date is now versioned and trackable. From here forward, each release adds an entry to this section.

  • Three-pane workspace: file navigator, terminal pane (with claude / shell split-button), polymorphic working pane (browser, markdown editor, HTML canvas).
  • Shared formatting toolbar across markdown editor and HTML canvas; markdown shortcuts on typing.
  • Full HTML canvas: edit live, comment threads in a sidecar, agent CLI ops (duo html new/query/get/set/replace/append/remove/attr/comment/comments).
  • Send → Duo: pill on text selection in any pane lands the quote in the active terminal.
  • Atelier visual identity: paper-cream surfaces, warm ochre accents, light by default, system / light / dark theme picker.
  • Duo subagent: Haiku-powered specialist for mechanical work, with bounded context and Duo-specific prompt.

Known issues at this version: ⌘T from terminal focus is currently swallowed (tasks.md § BUG-008); the +-claude-tab button doesn't auto-launch claude on first try due to a write race (BUG-009); about:blank still loads as the default new-tab landing (this FAQ replaces it in v0.2.0).

Getting started

How do I install Duo?

v0.1.0 is pre-distribution. To run it: clone the repo, npm install, then either npm run dev for the live build or npm run dist to produce an unsigned macOS DMG. First-launch self-install (auto-installing the duo CLI and the skill / subagent into ~/.claude/) ships in v0.2.0.

The terminal says "claude not found" — how do I fix that?

Duo expects the claude binary on your PATH (Claude Code CLI). Install it via npm install -g @anthropic-ai/claude-code or whatever the current install instruction is for your environment. Duo re-checks which claude on every new tab spawn, so a fresh terminal will pick up the installed binary.

How do I run duo commands from Claude or my own scripts?

The duo binary lives at cli/duo in the repo. For dev use, either invoke it directly (./cli/duo help) or symlink it onto your PATH (ln -s "$(pwd)/cli/duo" /usr/local/bin/duo). The Stage 18 first-launch installer will do this automatically when distribution begins.

Note: duo talks to Duo's main process over a Unix socket. It only works when Duo is running.

Using Duo

How do I open or create a markdown file?

Click any .md file in the file navigator (left column) to open it as the rich editor. To create a new one: click + on the working-pane tab strip, type a filename ending in .md, and hit Enter.

How does the HTML canvas work?

Open any .html file from the navigator and it renders as a live, editable canvas — what you see is what gets saved. The same toolbar as the markdown editor (heading picker, lists, tables, etc.) plus markdown shortcuts on typing. Comments live in a sidecar (<file>.html.duo.json) and never mix into the saved HTML. Claude can edit the canvas structurally via duo html * commands.

What is the "Send → Duo" pill?

When you select text in the markdown editor, the browser pane, or the HTML canvas, a small "Send → Duo" pill appears beside the selection. Click it; the selection lands in your active terminal as a formatted quote with provenance (path / URL trail) so Claude knows where it came from. Three formats available via duo selection-format a|b|c.

What's the difference between + and > on the terminal tab strip?

+ opens a Claude Code session in a new tab (auto-launches claude). > opens a vanilla shell. Keyboard equivalents: ⌘T from terminal focus opens claude, ⌘⇧T always opens a vanilla shell.

Why did clicking a link send me to my default browser?

Off-host URLs go to your default browser via shell.openExternal — the assumption being that work-restricted sites (SSO, internal pages, bookmarked tools) live on your real browser, not Duo's embedded Chromium. Domains on the external-domains list get this treatment automatically. Add or remove domains by editing ~/.claude/duo/external-domains.json.

How do I switch between light and dark themes?

The theme button is in the title bar (top-right). Click "System" / "Light" / "Dark" to cycle. From the CLI: duo theme system|light|dark.

For Claude / agent users

How do I ask Claude what Duo can do?

The What Duo does page lists every capability with a use case and the CLI invocation. From a Duo terminal, duo help dumps the full verb reference. Claude knows about both — just describe what you want and let it pick the right tool.

What is the Duo subagent?

A specialized Haiku-powered agent that handles mechanical Duo work (find this element, summarize the selection, route a quote to a terminal). Triggered automatically by Claude Code when the task fits — keeps Sonnet's working memory free for the actual problem you're solving.

How does Claude know it's running inside Duo?

Every PTY Duo spawns gets DUO_SESSION, DUO_SOCKET, DUO_VERSION, and TERM_PROGRAM=Duo in its environment. Tools branch on these. To check from a terminal: echo $DUO_SESSION — if it's non-empty, you're inside Duo.

Troubleshooting

Why does duo silently fail in some Claude Code sessions?

Claude Code runs each Bash tool call inside a macOS Seatbelt sandbox that gates Unix-domain-socket connections. Duo's bridge is a Unix socket — so duo commands invoked from a sandboxed Claude Code session can hang or return ECONNREFUSED. Workaround: invoke duo from a Duo-spawned terminal directly (those PTYs aren't sandboxed). The sandbox-tolerant transport ADR (in docs/DECISIONS.md) tracks the long-term fix.

Why doesn't ⌘T work from a terminal sometimes?

Known issue (tasks.md § BUG-008). xterm.js consumes ⌘T as PTY input by default; without the explicit allowlist entry, it never reaches Duo's window-level handler. Workaround: click + on the terminal tab strip directly. Fix lands in v0.2.0.

I clicked + for a Claude tab and the prompt is just showing "claude" without running.

Known issue (tasks.md § BUG-009). The auto-launch wiring writes claude\n too early — before the shell prompt is ready — so the newline gets dropped. Workaround: press Enter manually. Fix lands in v0.2.0.

Why does Duo open with "about:blank" in the right pane?

v0.1.0 still uses the browser-default landing for new tabs. v0.2.0 replaces it with this FAQ as the first-launch landing — a real "what is this and how do I use it" surface instead of a blank page.
