The Vault Guide

ENH-208 Networked work-notes on plain Obsidian conventions · Phases 1–2 (skill + capture UX)
A vault is a folder of markdown notes — YAML frontmatter, links between notes, and rollups — stored in one of two at-rest dialects. The OKF dialect (Duo's default) writes standard markdown relative links and slug filenames so the vault renders natively on GitHub; the Obsidian dialect writes [[wikilinks]] and a .obsidian/ folder. Either way, your work topics — people, initiatives, themes, meetings — form a graph, not a tidy hierarchy, and the gesture you type to link is identical. The vault stores that graph as plain files any human or agent can read; Duo adds capture and search, and Claude does the filing, linking, and rollups. The escape hatch that keeps it honest: an OKF vault opens correctly on GitHub and in Obsidian, and an Obsidian vault opens correctly in Obsidian — at all times.

1What a vault is

Everything is a file. A note is markdown with a YAML frontmatter header; an edge is a [[wikilink]] (in prose or in a typed frontmatter field); a type is declared by the note's folder plus its type: field. No database, no sidecar, no invented syntax — that is the whole format.

work-notes/                 ← the vault root (marked by .obsidian/)
├── .obsidian/              Obsidian's config — makes it a vault
├── templates/             soft schemas, one per type (query-excluded)
├── inbox/                  atomic captures land here, untyped
├── people/  themes/        registry folders for parentless types
├── initiatives/
│   └── Q3 Launch/           an initiative is a FOLDER it owns…
│       ├── Q3 Launch.md    …the folder-note (type: initiative)
│       └── Legal review.md …a milestone filed under its parent
├── notes/YYYY/MM/          time-bucket residue (no parent yet)
├── bases/                  vault-wide .base rollups
└── out/                    rendered rollup artifacts (regenerable)

Alice Park.md  ─ frontmatter ─          ─ prose ─
  type: person                          Owns [[Q3 Launch]]. Primary
  role: Product lead                    contact for [[Pricing]].
  aliases: [Alice]      ↑ typed edges     ↑ prose edges
Why it matters: because the vault is just files, it survives Duo entirely — it syncs over git, opens in Obsidian, and is intelligible to agents that have never heard of this feature. Peek at any vault's whole shape with duo vault schema, or find vaults under a folder with duo vault list.

3OKF vs Obsidian mode

A vault stores its graph in one of two at-rest dialects. Both are the same graph model — same notes, same edges, same templates and filing rules — written by a different serializer. You pick the format once, when you create the vault; the active vault then tells Duo's editor which dialect to write. The gesture you type to link is identical; only what lands on disk differs.

OKF mode default

Standard markdown relative links + slug filenames + a title: / id: frontmatter pair. Renders natively on GitHub, opens in any editor — and in Obsidian. Best for shareable / published knowledge bases.

[Customer Orders](./people/customer-orders.md)

Obsidian mode

[[wikilinks]] resolved by basename + a .obsidian/ config folder + .base rollups. The original ENH-208 behavior. Best when you live inside Obsidian and never publish to GitHub (wikilinks render as literal text there).

[[Customer Orders]]

What differs at rest — and only at rest:

  you type   [[Customer Orders]]  in either mode

The gesture is identical; only storage differs (D3). In OKF mode the [[ ]] is input only — the moment the link resolves, the editor expands it to a standard markdown relative link, so no double-square-bracket link ever persists in an OKF vault. The same gesture inside a frontmatter value rewrites to a quoted relative-path string on commit (D7). In Obsidian mode the wikilink is written through unchanged.

↓

a vault that renders on GitHub and opens correctly in Obsidian — OKF mode does not break the "opens in Obsidian always" guarantee, because Obsidian renders standard markdown links natively
Marker-wins detection (D4). Duo decides a vault's mode by reading the in-vault marker live (an explicit okf_version ⇒ OKF; a .obsidian/ ⇒ Obsidian) — never a cached registry flag, never link-style sniffing. The editor picks up the active vault's mode automatically and falls back to Obsidian if neither marker is present; duo vault list shows the vaults detected from the current folder.
Moves self-heal (D5). OKF relative links are path-bound, so a file move could dangle them — but Duo owns moves: duo vault mv rewrites every inbound link, and an auto-relink pass runs whenever an OKF vault opens, re-resolving any out-of-band moves (Finder, git) by stable id: then slug fallback. Repair the rest on demand with duo vault relink (which reports anything ambiguous or broken). The CLI requires --format on purpose; only the New Vault dialog defaults it to OKF.

4Types, templates & filing

A type is a templates/<type>.md — a soft schema. Its meta keys say what an entity of that type expects and where it files (D19); the rest are the fields a new note inherits. Nothing is enforced — processing validates against it later.

templates/milestone.md           the template…
  type: milestone                meta — the type name
  filingParent: initiative       meta — files under its initiative's folder
  filingLoose: true              meta — loose, not in a subfolder
  initiative:  owner:            fields — seeded empty on a new note
  status: on-track  due:

         ↓  a new milestone inherits the fields, then files by the rule

initiatives/Q3 Launch/Legal review.md   ← lives under its parent initiative
Filing ruleTypesWhere the note files
folder:person, themetheir registry folder (people/, themes/) — parentless
filingParent:milestone, meetingunder the parent named by that frontmatter field (milestone → its initiative)
folderNote: trueinitiativeowns a folder named after it; the only type that can be a filing parent
— no parent yet —any parentedtime-bucket notes/YYYY/MM/; processing re-files when a parent emerges
Folder layout is ergonomics only. Every query is frontmatter-driven, so a note keeps all its [[links]] when it moves — filing loses no edges. Completed initiatives are proposed for archive/YYYY/ by processing (D20), never moved automatically. Read the live rules with duo vault schema.

When a note mentions someone or something new, it becomes a real entity from the matching template — and your cursor never leaves the note you're writing.

the stub filed silently in the background — nothing interrupts you

In the editor: type [[Onboarding and the [[ suggester offers a New: row. Picking it completes the link and pops the type picker — your template types plus "+ new type…" — and the stub files by the filing rules in the background, silently: no tab opens, the caret never leaves the note, and ⎋ creates nothing. One-word names for now — the [[ suggester closes on a space, so multi-word entities take the narration path. By narration: "Jordan Lee owns pricing now" — Claude confirms it's new with duo vault schema (checking aliases), then runs duo vault stub person "Jordan Lee" — the same code path the picker uses.

The same gesture, two on-disk results (D3). What persists depends on the vault's mode — the gesture and the popover are identical (see chapter 3):

OKF vault — expands on resolve

…tracks [Onboarding](./initiatives/onboarding/onboarding.md) for Q3.
     ↑ standard markdown rel link; filed at
       initiatives/onboarding/onboarding.md (slug)

A fresh stub uses the human name you typed as the link text (D6); the slug lands in the filename + path, the name in title:.

Obsidian vault — wikilink unchanged

…tracks [[Onboarding]] for Q3.
     ↑ wikilink, basename-resolved; filed at
       initiatives/Onboarding/Onboarding.md

The [[ ]] persists as written; the filename keeps the human name verbatim.

Picking an existing note from the suggester (rather than the New: row) uses the on-disk slug as the link text in OKF mode in v1 (no title parsing yet); a stub keeps the human name. Obsidian mode is unchanged either way.

Shipped in Phase 2: [[New Name]] ⇥ on the New: row → the type-picker popover → stub created in the background; the caret stays put, ⎋ creates nothing. In an OKF vault the link expands to [Name](./..md) on resolve (D3); in an Obsidian vault the wikilink is written through unchanged.

6Capturing a note

Capture is fast and lossy by design. A thought becomes an atomic note in inbox/, untyped — a later processing pass files and links it. Nothing to organize in the moment.

YOU
"note from the pricing sync — Alice wants the fee model by Friday"
↓
CLAUDE
runs duo vault capture --template meeting --text "…", links [[Alice Park]] + [[Pricing]], stubs anything new
↓
FILES
inbox/2026-06-09 143205 pricing sync.md — timestamped to the second (so back-to-back captures never collide), captured: stamped, body filled
inbox/2026-06-09 143205 pricing sync.md
  ---
  captured: 2026-06-09
  type: meeting           ← from --template
  attendees: []  date:    ← fields seeded empty
  ---
  Alice wants the [[Pricing]] fee model from [[Alice Park]] by Fri.
The verb: duo vault capture [--template t] [--text "…"] [--title "…"] [--open]. The chord: ⇧⌘N drops the same untyped inbox note into the default vault (else the active file's vault) and opens it focused; if neither resolves, the error points you at Settings → Default Vault. And @today-style smart date tokens (today / tomorrow / yesterday, ISO + long-form, plus now) rank in the @ suggester — picking one inserts plain text.

7Finding things

Four ways to get around the graph — full-text, and three that follow edges. All emit JSON Claude can act on; all resolve wikilinks by basename, so they keep working after a note is filed somewhere new.

Full-text search

Every line that matches, with file + line number.

duo vault search "pricing"

⌘⇧F opens the same search as a palette over the default vault (else the active file's vault) — results grouped by file with line + excerpt; Enter opens the file at that match.

One wrinkle: inside the browser pane's find bar, find-previous is ⇧Enter only (⌘⇧F there opens this palette); the editor and canvas find bars also keep their local ⌘⇧F.

Backlinks

Who links to this note — including typed frontmatter edges (a milestone's initiative:), not just prose.

duo graph backlinks "Alice Park"

Orphans

Notes with no links in or out — a tidy-up list for processing.

duo graph orphans

The corpus

The whole schema at a glance — types, entities, aliases, props, observed enum values.

duo vault schema

Basename resolution is what makes filing safe: move Legal review.md into its initiative's folder and every [[Legal review]] link still points at it.

8Running docs & promote

Not everything deserves its own file on day one. Keep a low-ceremony series as one running doc — a section per entry — and promote a section to its own entity only when it earns properties or a place in a rollup. (A link can point inside a note: [[Meetings#2026-06-09]] — the # targets that dated ## heading.)

Before — one running doc

Q3 Launch/Meetings.md
  ## 2026-06-02
  kickoff; scope agreed
  ## 2026-06-09
  pricing pushed a week
     ↑ [[Meetings#2026-06-09]]

After — the section promoted

Q3 Launch/Meetings.md
  ## 2026-06-09
  ![[2026-06-09 pricing sync]]
     ↑ embed left behind

Q3 Launch/2026-06-09 pricing sync.md
  type: meeting · attendees: […]

How: ask Claude to "promote the 2026-06-09 section." It splits that ## section into an entity file from the matching template and leaves an ![[embed]] behind (the leading ! pulls the new note's content inline where the section was — Obsidian calls it a transclusion) — reversible by inlining the embed. It's a skill choreography over the existing file + duo doc verbs; there's no duo vault promote verb in v1.

Fast-follow: editable transclusion (inline-editable embeds) is the deferred Duo-native upgrade that makes discrete files read & edit as one doc.

9Generating a rollup

A rollup is a view computed from frontmatter — "open milestones for this initiative, grouped by owner, with a due chip." Duo uses plain Obsidian Bases (.base files + embedded blocks), so the same view renders in Obsidian too.

YOU
describe the view in prose
↓
CLAUDE
runs duo vault schema to get the real type names + enum values, then writes the .base — vault-wide in bases/, or an embedded … == this block in the type template so every entity inherits it (initiative == this means "only rows whose initiative field points back at the note being viewed")
↓
SCRIPT
duo base lint checks every type, [[entity]], enum value & function against the corpus — with "did you mean" fixes — looping until clean (it's advisory; it never blocks)
↓
SCRIPT
duo base render <note> --open evaluates it over live frontmatter and opens the result as a tab
The headline pattern: an embedded block filtering initiative == this lives in the initiative template — so every initiative gets its milestone rollup with zero per-note setup.

initiative == this · 4 rows · grouped, with a due chip

Duo-owned render — table/cards/list is never user-authored; cell styling comes only from html() / icon() formulas (D16).
You don't need to memorize the syntax — lint tells you when you've stepped outside it. The engine is a locked Bases subset (filters, if(), link == this, date math, html()/icon(), groupBy, summaries, child→parent backlink rollups). Anything else renders as a ⚠ cell rather than breaking.

10Refreshing a rollup

A render is a build artifact, not a live cache — and it says so. Every render carries a visible stamp at the top, so staleness is always detectable:

BUILD ARTIFACT — regenerate: duo base render Q3 Launch ·
generated 2026-06-09T18:41:19Z · source hash 335e980971a9 ·
date-relative formulas as of 2026-Jun-09 · 6 notes, 1 rendered base

Edit a milestone's status and the vault's content changes → the next render computes a different source hash → you can see the artifact is stale and re-render it.

Live

A throwaway render opened straight as a tab — not persisted.

duo base render <note> --open

Artifact

Written to the vault's out/ (or --out), stamped — share it, commit it, diff it.

duo base render <note> --out report.html

v1 refresh is on demand (re-run the verb). Re-render on tab-focus is the fast-follow; a file-watcher + scheduled re-render are deferred — by design, no silent staleness.

11Processing

"Process my vault" is a single reviewable pass that does the housekeeping capture deliberately skipped — and every change is a proposal, never silent.

YOU
"process my vault"
↓
CLAUDE
builds the work-list live — stale inbox (> 1 week), untyped notes, missing required fields, unresolved [[links]], ⚠ flags, duo graph orphans (the same list bases/processing.base shows you)
↓
CLAUDE
files inbox notes by the D19 rules · repairs frontmatter + links as tracked suggestions you accept or reject in the editor · promotes sections · proposes archiving completed initiatives
↓
FILES
a dated report note links every touched file + each proposed move
↓
YOU
accept / reject each suggestion in the editor (duo doc accept / duo doc reject)
Scale safety: processing edits only through the surgical CriticMarkup paths and sanity-checks git diff --numstat is insertion-sized — never a whole-document rewrite.
The model that makes it trustworthy: tracked suggestions + a report note + file-moves listed for approval mean a processing run is fully reviewable — the same property that lets it run unattended on a schedule later.
