2 · The choice, in context

After you paste a GitHub file URL into the Open bar, the resolver detects it and the bar offers the fork before doing anything irreversible:

Opengithub.com/dudgeon/duo/blob/main/docs/roadmap.md
✓ Recognized — a markdown file in dudgeon/duo @ main. How do you want to work with it?
📄 Open just this document fast
Pulls only what's needed into a hidden working copy and opens it like a local file. Edit, then "Propose changes" ships a PR back.
no repo added to your navigator
📦 Clone the whole repo project
Clones dudgeon/duo to a folder you pick, adds it to the navigator, and opens this file — full git, branches, terminals.
uses Duo's existing Clone flow
Remember my choice for dudgeon/duo Esc cancel

Presented as two equal-weight choices (no pre-selected default) so the flow genuinely asks, per your note. The "remember for this repo" checkbox is the escape valve so a power user isn't re-asked forever — see DR2.

3 · Clone convergence — today vs proposed

Duo already ships a clone flow: duo clone <url> [dir] (ENH-151, v0.7.0) → core/git/clone.ts runClone() (gh-preferred, git fallback), plus CloneModal.tsx (URL + parent-dir picker + collision detection + auth banner) reached from File ▸ Clone… and the FileTree right-click. On success it sets the navigator root. The question is whether ENH-224's new "clone the repo" branch re-uses that, or grows a parallel one.

Recommendation — yes, converge now, but light. The clone internals are already a clean substrate and the modal is shipped + fixed, so this is routing + parameterizing, not a rewrite: (1) give runClone an optional depth + openAfter (it already takes targetDir/cwd); (2) have the ⌘O "Clone the repo" choice open the existing CloneModal prefilled with the URL + an "open doc.md after cloning" toggle; (3) keep the managed-sparse path for "Just this doc." Doing it now (while the Open flow is being specced) avoids a second, divergent clone entry point later — the expensive outcome. A full rewrite of the modal into the Open bar is not warranted.
