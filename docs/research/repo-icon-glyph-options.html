Repo-root glyph options — Navigator git indicator

Sprint 17 ENH-152a v2 round-5 Currently using ⎇ (macOS option-key glyph) — not actually a git symbol. Pick a more recognizable replacement.
Why this matters. The repo-root indicator sits next to every git-repo folder in the Navigator. It's small (11px), needs to read as "this folder is a git repo" at a glance, and changes color (ink-mute → accent → warn) to reflect state. The current ⎇ is the wrong glyph — it's macOS's option-key symbol, not a git icon. Below: six candidates rendered at the actual 11px size (top of each row) and a 24px zoom (next to it) so micro-detail loss is visible. Pick which works best.

Side-by-side comparison

Each candidate at 11px (actual Duo nav size) and 24px (zoom). All shown in the "dirty" accent-orange state.

0 · Current: ⎇ (Unicode option-key) — baseline. Generic, easy to mistake for keyboard shortcut.
A · Lucide git-branch — the canonical "branch off the main line" visual. Used by VS Code, Linear, Vercel. Most universally read as git.
B · Lucide git-fork — Y-shape (two parents → child). GitHub's "fork" icon family. Implies "repo I could fork" more than "git folder."
C · Lucide git-commit-horizontal — node-on-a-line. Reads as "commit" or "node" more than "branch." Simplest shape.
D · GitHub Octicons git-branch (filled) — GitHub's own glyph. Solid fill = denser, reads strong at 11px even with state-color. The same icon GitHub.com uses inline.
E · GitHub Octicons repo — book-with-bookmark. Reads as "repository" (the noun) rather than "branch." Same icon GitHub.com uses to label repos.
F · Custom "branch dots" (filled circles + line) — same git-branch composition as A but with solid circles. More visual weight at 11px; harder to lose when the navigator is busy.
