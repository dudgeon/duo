BUG-191 · Ghost project tile (zero open members) Medium

Root cause — frozen terminal launch-cwd. A tile renders only if its root owns ≥1 member or is pinned. A terminal's cwd is set once at construction (makeTab) and is never rewritten — not when the shell cds elsewhere, not when the shell process exits. So a terminal whose launch directory was under project A keeps qualifying A on every derive, even after you've navigated away or the shell is dead. A pure zero-member unpinned tile is provably impossible in the derivation layer, so a ghost is always one of three buckets:
  1. Frozen-cwd / dead-shell terminal still in tabs[] — confirmed, refuteCount 0 · pip-less · the primary defect.
  2. Deleted-file working tab never pruned from fileTabs[] — secondary · pip-less.
  3. Pinned tile — shows the pin pip · working-as-designed (D12) or the FOLLOWUP-037 deleted-marker caveat.
Open terminal, launch cwd ~/GitHub/duo (project A, A's only member) → Inside the shell: cd ~  (or the shell exits) → tabs[].cwd still says ~/GitHub/duo — never updated → Tile A persists, pip-less, "0 things open"

BUG-192 · Recursive jitter / force-quit loop on right-click close Low

Root cause — not pinned down by static analysis. Every concrete loop candidate was refuted across all 3 lenses — they all converge in today's build (value-equality bailouts, monotone probe caches, a raw-cwd guard, and universal focusedProject === null early-returns). The best-supported remaining explanation is the unguarded cross-store setState burst inside handleCloseProject: setTabs (with a nested setActiveTabId inside its updater) + setFileTabs + setActiveWorking + setFocusedProject, optionally split by an await dialog.confirm, feeding the live effect cluster (browser-redirect machine E5/E6/E7 + auto-spawn E9) while membership probes are still settling — with no in-flight / re-entrancy guard (FOLLOWUP-032, never implemented). You did force-quit, so a non-convergent region is reachable in practice; it most likely lives in the burst → effect-cluster interaction under specific timing (closing a non-focused tile keeps focus non-null and voids the convergence proofs, + a browser member tab + probe lag).

Cross-cutting — one root family, two faces

Both bugs descend from the same design facts: membership is fully re-derived every render (shared/projects.ts:259-271), probe caches are monotone and never invalidate (useProjects.ts:84-94), and there is no reactive prune of dead terminals / file-tabs.

  • BUG-191 is the steady-state face — a stale member lingers in tabs[]/fileTabs[] and quietly keeps a tile alive.
  • BUG-192 is the transition face — the close mutates those same arrays across multiple stores while membership probes lag, driving the effect cluster.

Reactively pruning stale members (191-b) shrinks the very arrays the close handler thrashes, narrowing 192's probe-pending window — a mitigation, not a cure (it leaves the re-entrancy / nested-setState hazards). The cleanest combined posture is 191-a (live-cwd tracking) + 192-a (atomic guarded handler): the rail reflects live state and the close becomes a single safe transition. The two are independent enough to ship and smoke-walk separately.
