Vault vs Obsidian — an honest assessment

Pre-build review ENH-208 2026-06-09 · audits docs/prd/enh-208-vault.md (D1–D22) against Obsidian 1.13 core + ecosystem
What this is. An adversarial self-review, requested before any build investment: for every PRD capability — are we REINFORCING Obsidian patterns (using them as-is), DUPLICATING them (rebuilding what Obsidian already does), or DIVERGING (building what Obsidian cannot do)? Facts about Obsidian were re-verified against official docs today — including three that cut against us. Verdict up front; the receipts below; three decisions at the bottom.
Verdict

Yes — but the case rests almost entirely on the agent layer, and the phases are not equal. Phase 1 (skill + CLI verbs) is ~85% divergence: processing with reviewable tracked changes, corpus-as-schema validation, prose-to-base authoring, headless publishing — none of which exists in Obsidian or its ~66-server MCP ecosystem. Build it immediately. Phase 2 is mostly justified duplication (capture ergonomics where you already work). Phase 3 (in-app rollup tabs) is where duplication concentrates — Obsidian renders the same .base files natively, with property-editable cells we won't match in v1 — so it should be gated on observed Phase-1/2 habit, not built on faith. The single biggest risk is not any one feature: it's drift toward "Duo becomes a worse Obsidian." The mitigation is already locked (D1 strict compat): treat Obsidian as an official companion, not a rival — and let it keep the jobs it does better.

Division of labor — said out loud

Obsidian keeps these jobs (we deliberately don't chase)

  • Backlinks pane, tags, graph view, outline
  • Search operators, regex, embed-aware search
  • Editable base cells (property write-back)
  • Embeds/transclusion rendering
  • Mobile capture + sync — strict compat means the phone story is "install Obsidian mobile," and that's a feature, not a concession
  • A decade of plugins

Only the Duo + agent stack does these

  • Processing: reviewable tracked-change refactors of your corpus, accept/reject beside the conversation
  • Corpus validation — the vault as its own schema, "did you mean" against what actually exists
  • Rollups authored from prose, linted before they render
  • Headless everything: scheduled processing, CI-able lint, artifacts from cron — Obsidian not running, not installed
  • Child→parent rollups past the Bases boundary
  • Capture without leaving the window where the work happens

The steelmen — answered honestly

"Why not just use Obsidian + an MCP server? There are ~66 of them."
The serious alternative, verified today: Local REST API + MCP servers are real and mature-ish. Two honest answers. (1) The agent never needed Obsidian — Claude works the files directly; an MCP adds a middleman that requires Obsidian running. (2) What that stack cannot give: agent edits land raw — no tracked changes, no accept/reject, no report notes — and the human reviews in a different window from the conversation. The pairing premise (selection sharing, duo verbs on the open note, CriticMarkup review in-window) is the actual product; MCP-driven Obsidian is agent access without agent collaboration. If that premise is wrong, Duo itself is wrong — this feature isn't where that bet gets decided.
"You're building a second .base renderer that will chase Obsidian's spec forever."
True, and the tax is real (kanban/calendar views are on their roadmap). Contained three ways: the engine is pinned to the documented subset (unknowns render as ⚠ cells per D15, never crash); the renderer is needed anyway for headless artifacts (D13) even if in-app tabs never ship; and the in-app surface (Phase 3) is the gated part. Worst case we keep a small headless renderer and Obsidian remains the live viewer — that fallback is decision Q1-C below, and it's a respectable outcome, not a failure.
"Duo's editor will always be a worse Obsidian. You're on a treadmill."
Correct — if we chase editor parity. The locked design refuses the treadmill: the deferred ledger (backlinks pane, tags, graph, editable embeds) is a list of things we may never build, because D1 strict compat means the user opens the same folder in Obsidian whenever they need them. Duo's editor only has to be good at capture and review — the two jobs that must happen next to the agent. The moment a PRD line item exists to make Duo a better Obsidian rather than a better pair surface, it should die in review. (@today came closest this round; it survives on size alone.)

Decisions

Q1 · The verdict

Does the vault feature set still get built, and in what shape?

The assessment supports building, with skepticism concentrated on Phase 3. This locks the shape.

Q2 · Companion stance

Is Obsidian officially a companion app, embraced in the Guide?

This decides the editor-treadmill question permanently: either the Guide says "open your vault in Obsidian for backlinks/graph/mobile" with pride, or those become Duo roadmap debts.

Q3 · Engine policy

How does the .base engine relate to Obsidian's evolving spec?

Bases ships new views and functions several times a year. This sets the maintenance contract before the first line is ported.
