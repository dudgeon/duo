Agent-agnostic Duo — Claude Code + Codex

RESEARCH ENH-189 Max-effort research sprint · 2026-05-28 (rev 2) · branch claude/duo-agent-agnostic-research-9y1t3
What this is. A decision-bearing audit of every place Duo is wired to Claude Code, scored for what happens under OpenAI's Codex CLI — works, no-ops, or breaks — with options for each, weighed by upfront build vs ongoing maintenance. Every Duo touchpoint below was read from source; every Codex claim was checked against OpenAI's docs (see the verification note at the foot). Answer the decision cards and hit Copy decisions to round-trip back to Claude.
The thesis. The duo CLI + socket bridge are agent-neutral and run under Codex today. Teaching Codex about duo is also cheap, because SKILL.md is now a cross-harness open standard — Codex auto-discovers skills from ~/.agents/skills/ with the same progressive-disclosure behavior as Claude Code. The genuine residual work is a thin lifecycle layer; most of it is cheap parameterization (launch, presence, marker, doctor, config pane), and only two pieces are real gaps because they lean on Claude-private mechanisms: the always-on priming shim (Codex has no per-session system-prompt flag) and session capture/resume (Claude's cwd-indexed transcript store vs Codex's date-bucketed one). Keep coupling on public contracts — the skill standard, codex resume --last, MCP — and avoid reverse-engineering Codex's private session files.

1 · The architecture in three rings

Every Claude-Code touchpoint falls into one of three rings. The bridge works as-is; teaching converged onto a shared standard; the lifecycle layer is where the work is — and most of it is cheap.

Maintenance-burden law. Coupling that reads a tool's private file format (the rollout JSONL schema) or shells its private flags (--append-system-prompt, which Codex doesn't even have) is a standing drift liability — it breaks silently on the next upstream release. Coupling that rides a public contract (the SKILL.md standard, a documented subcommand like codex resume --last, env vars, or MCP) is durable. Every option below is graded on which side of that line it sits.

5c · Teaching Codex that duo exists

No-op

Do nothing

User manually tells Codex about duo each session. Zero build, zero maintenance — but the autonomous-agent magic silently never happens.

Recommended

Sync skill → ~/.agents/skills

Ship the existing SKILL.md to ~/.agents/skills/duo/ (or as a Codex plugin). Open standard, progressive disclosure, implicitly invoked. Near-verbatim; just extend sync:claude.

Optional

Global ~/.codex/AGENTS.md

For always-on Duo-session behavior the skill can't cover (the shim's old job). Persistent + applies to all Codex sessions, not just Duo's — use sparingly.

Durable

Duo as MCP server

Expose the verbs as self-describing MCP tools both harnesses auto-discover via their config. Bigger build, near-zero drift.

Decision D3 chooses among these (not mutually exclusive — sync the skill now + MCP later is a sequence).

6 · Decisions

Seven decisions, ordered from the spine (D1) outward. Recommended picks are pre-tagged; override freely and leave notes.

Decision 1 · The spine

What target posture for harness-agnosticism?

Everything else inherits from this. The trade is reach vs. the standing cost of keeping two (or N) integrations honest as both tools ship weekly.

Decision 2 · Abstraction shape

If we go agnostic, how do we model "a harness" in code?

Only bites under D1=B/C. Determines how a new harness (or an upstream change) ripples through the codebase.

Decision 3 · Teaching the agent

How does Codex learn that duo exists?

Smaller than feared: Codex supports the SKILL.md open standard (progressive disclosure + implicit invocation) from ~/.agents/skills/, so the existing skill ports near-verbatim. Options aren't mutually exclusive.

Decision 4 · Launch

How do we open Codex as a tab? (mockup 5a)

The tab-kind enum is 'shell' | 'claude' today (shared/types.ts:7). This is a UI + data-model choice.

Decision 5 · Presence pill

How do we detect a live Codex process, and what does the pill say? (mockup 5b)

The probe matches comm === 'claude' (core/claude-presence.ts:143). The fix is small; the question is how general to make it + the pill copy.

Decision 6 · Session capture & resume

Do we rebuild resume pills for Codex — and how?

Where the ongoing-maintenance tax is highest. Codex's transcripts are date-bucketed (~/.codex/sessions/Y/M/D/rollout-*.jsonl) with a different schema, so per-cwd reconstruction is both harder and a standing drift liability — but codex resume --last is already cwd-aware.

Decision 7 · Config pane + doctor

What happens to the ~/.claude navigator pane and duo doctor? (mockup 5d)

Both currently assert Claude paths (useUserClaudeNavigator.ts:57; cli/duo.ts:1882). For a Codex-only user the pane shows the wrong thing and doctor shows false red.

Recommended throughline (one coherent path)

D1=A · D3=B (MCP D later) · D4=A · D5=A · D6=A→B · D7=C→A.

Translation: lean on the already-neutral core; teach Codex by syncing the existing skill to ~/.agents/skills/ (the format is the shared standard, so near-free); make only the cheap, durable parameterizations (codex tab kind, presence matcher, marker set, neutral author default); and degrade the two genuinely Claude-private features — the always-on priming shim and rich session capture/resume — rather than reverse-engineering Codex's private store (offer codex resume --last instead). Scope Duo-as-MCP-server as the longer-term spine for exposing duo as tools. Net: most of Codex's value ships in a small, low-maintenance diff.

If the goal is broader than Codex (Gemini CLI, aider, …) — note those also use the ~/.agents/skills/ standard — that's the signal to escalate D1→B and D2→B, since the adapter's ongoing cost is only justified by a third harness.
