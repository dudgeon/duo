Merged Open + Clone surface

ENH-221 DR3 / DR5 2026-06-20 · the merged-UI you asked to see · pairs with the flow map
What this is. You asked to see what "merging the flows" actually looks like — one ⌘O surface that handles open a doc and clone a repo as a single progressive flow, instead of bouncing to a separate Clone modal. Below is that surface state-by-state. It also fixes the clone success screen: today the hero button is "Clone another" (optimizing the rare case) — replaced with a clear success message and an Open / Done hero, with "clone another" demoted to a quiet link. And per your note, the paste field stays primary but gains a Browse… button that opens the native OS picker so local files and folders can be chosen with the mouse.

It's the same overlay throughout — only the body changes as Duo learns what you pasted. No modal hand-off.

Net of the merge. One surface from paste → choice → clone → success, so the user never context-switches to a modal; the inline confirm still carries the shipped modal's destination picker + collision + auth checks (nothing lost); and the success screen finally points at the thing you were trying to reach. The cost vs. the lighter "hand off to the existing modal" path is real — see DR1.

3 · Decisions

Decision DM1

How merged should it actually be?

The mockup shows the full inline merge. The lighter alternative (my earlier DR3 rec) keeps the shipped modal and just opens it prefilled — less build, slightly less seamless.

Decision DM2

The success hero — Open or Done?

You said make the hero "Done" or "Open" (not "Clone another"). When does each win?

Decision DM3

The native picker — one button or two?

Paste stays primary; Browse… is the mouse path. On macOS a single open dialog can allow selecting either a file or a folder. Picking a file opens it in its viewer; picking a folder roots the navigator there.
