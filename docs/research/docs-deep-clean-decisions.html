1 · Start with the Navigator — it knows where you are The left column is the navigator, and it does two jobs at once. The obvious one: a file tree rooted at your home folder. The less obvious one, and the reason it's first: it's how you tell Claude where you are… a slim ribbon shows your branch and how many files are dirty, and changed files get a small orange dot you can hover for the +42 / -7 diff.
2 · The Terminal is the main event More of my day happens in the terminal now, so in Duo it sits front and center, tabs across the top like a browser. Each tab is a conversation… the Return key does what your muscle memory expects from Slack — Enter sends, Shift+Enter makes a new line.
3 · The Canvas: one slot, many shapes The right pane is what I call the canvas — though "canvas" here just means "the slot," not any one tool. Open a markdown file and it becomes a writing surface; an HTML file, a live page; a JSON payload, a collapsible tree. (Then H3 sub-sections:)
3a · The markdown editor that feels like home It's all markdown under the hood — which is what lets the file travel cleanly into git, into Claude's hands. But unless you open the source view you never think about markdown… Select a sentence and ⌘⌥M leaves a comment, exactly like Docs — except the comment lives inside the file as plain text, so Claude can read it and reply.
3b · The HTML canvas, for things you can see Claude can edit a single section of the page without touching the rest… you can say "rewrite just the pricing table" and it surgically replaces that one block. This is also where that earlier example lands: highlight an element, tell Claude "make this button inactive until the prior steps are done."
3c · The JSON / YAML viewer, for the configs you inherit You probably don't write JSON, but you get handed it constantly… instead of a wall of brackets you get a collapsible tree, and if you typo something Duo tells you in plain English ("Did you forget a closing brace?").
3d · The Browser, a real Chrome tab inside the window Highlight anything on a page, or point at a single button with ⌘⇧C, and a "Send → agent" pill appears… (one note for anyone on a locked-down work machine: by default Duo only renders local files and sends real websites to your normal browser).
3e · Split View, when one file isn't enough Split View puts two documents side-by-side — I use it to read a spec next to the notes I'm taking on it. Press ⌘\ on any open file to send it to the side; it survives a restart.
3f · Layout & actions: bend the window to the task Reading something long? Give the canvas more room, or collapse the terminal to a rail. Or — the part that ties it all together — just ask Claude ("collapse the terminal and navigator so I can focus").
4 · The CLI — the thread that sews it all together You will almost never type these commands yourself — they're the hands the agent reaches for when you ask in plain English. "Open my roadmap and scroll to the open-questions section" becomes duo open and duo doc goto under the hood… A normal IDE gives you tools; Duo hands the same tools to the agent sitting next to you. When you ask for something, Claude doesn't describe what to click — it clicks.
