Rollup viewer & editor — four layout directions

ENH-243 Rev 2 2026-07-02 · vault workspaces · builds on the ENH-228/229 rollup engine
What this is. A GUI for viewing and building rollups in any workspace with a detected vault (OKF included). It appears as a tab beside the vault surface, lists all rollups, and lets the user create or reshape one entirely through UI — entity types, multi-depth group-by (e.g. status → org), and filters — with live re-render and live save. The config file rides in the repo but is never hand-edited; a doctor action hands a broken config to Claude. Entity attributes are edited by flipping typed frontmatter values in an inspector subpane (replacing the earlier drag idea). Hovering an entity reveals its path; clicking opens it in Duo — try it on the wireframes below, the hover is live. Rev 2 folds in the owner's lean toward Layout A.

What every layout must house

RequirementNotes
Rollup list + createEnumerate every rollup in the vault (engine: duo rollup list); “New rollup” starts from a picked entity type.

GUI builderEntity type(s) → ordered group-by levels (1..n deep, reorderable) → filters. No YAML ever shown; config file is machine-owned.
Live save + refreshEvery builder change persists immediately and re-renders; a manual refresh re-reads the corpus.
Frontmatter flip subpaneSelect an entity → inspector shows its typed attributes with one-click flips (bool toggle, enum cycle/pick, date/text inline) — each flip writes the note’s frontmatter, undoable.
Hover path · click opensHovering any entity row reveals its vault-relative path; clicking opens the note in Duo (duo open semantics).
DoctorWhen the config fails to parse/lint, a “Fix with Claude” action replaces the broken view.

For

  • Column + swimlane maps two group levels to two visual axes — no other layout does that.
  • Board/Table toggle covers both work-management and reporting reads from one config.
Against
  • Its hero interaction (drag) was just retired — flip-editing lives equally well in any layout.
  • Only shines when group level 1 is a small enum; collapses for org-first or 3-level rollups.
  • Builder and editor both hidden behind slide-overs — most modal of the four; most new rendering work.
Shared plumbing (applies to whichever layout wins)
  • Engine, not new query code: the GUI reads/writes the ENH-228/229 rollup config (machine-owned; OKF-compatible) and renders through the same evaluator as duo rollup render. Multi-depth group-by = an ordered groupBy list in the config. The builder's vocabulary (types, fields, enum values) comes from duo vault schema, which also types the flip controls (bool → toggle, enum → picker, date → date field).
  • CLI parity (rule 4): everything clickable needs verbs — roughly duo rollup new/set/show/doctor plus a frontmatter-flip verb (or reuse of the existing note-write path).
  • Undo: frontmatter flips land through the normal note-write path, so file-history (ENH-221) already gives restore; the toast is a convenience wrapper.
  • Hover path / click-open: every rendered entity row carries its vault-relative path (tooltip on hover) and opens via the duo open path on click — same affordance in all four layouts.
  • Doctor: “Fix with Claude” sends the broken config + lint errors to the active terminal session as a prepared prompt.

Decisions

Decision 1 · Primary layout

Confirm the layout direction for the rollup viewer/editor.

You leaned Layout A — it's marked recommended and its wireframe now shows the stacked inspector (definition + frontmatter flip subpane) and two-level grouping. Confirm or override; hybrid notes welcome.

Decision 2 · Flip-edit apply semantics

When a frontmatter value is flipped in the inspector, how does it apply?

Flips are typed and scoped (one field, one note), so they're lower-risk than drag was — but they still rewrite a file and can re-file the row into another group mid-read.

Decision 3 · Doctor surfacing

Where does “Fix with Claude” run when a rollup config is broken?

The config is machine-owned, so the GUI must never dead-end on a broken file. All options show the diagnosis in place of the rollup.
