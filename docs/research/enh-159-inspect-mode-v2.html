ENH-159 v2 — Inspect mode UX redesign

Decision gate 5 questions Filed 2026-05-16 · v0.7.0 walk surfaced · parent ENH-159 v1 shipped today (PR #51)
The bug. ENH-159 v1 shipped today: duo inspect + ⌘⇧C toggle inspect mode in the browser pane. Click an element → captures DOM context + auto-ships to terminal. Walk fail: (a) auto-ship is wrong — owner wants click-to-freeze + explicit ship; (b) CLI-only toggle is too narrow — needs right-click entry; (c) selection-observer doesn't pause during inspect mode — pill still appears on text-select.

Note: the CLI verb shape + DOM-context paste format passed the walk. This v2 is purely about the UI flow + entry points + observer fix.

1 · The three-state machine (proposed)

State A · OFF (default)

Normal browsing

  • Selection observer active
  • Hover = nothing visual
  • Click = page interaction
  • Text-select → Send→Duo pill
→ B via duo inspect / ⌘⇧C / right-click "Toggle inspect"
State B · ON, hovering

Picking an element

  • Selection observer PAUSED
  • Hover = orange outline + tooltip
  • Click = freeze element (→ C)
  • ESC = exit (→ A)
→ C via click on element
→ A via ESC
State C · ON, frozen

Confirm-and-send

  • Outline LOCKED (4px solid)
  • Send-to-Duo pill near element
  • Click pill = ship + exit (→ A)
  • ESC = unfreeze (→ B)
→ A via pill click
→ B via ESC or click-outside (per Q2)

The shape mirrors Chrome DevTools' element picker (click selects + locks, ESC exits) but adds an explicit "ship it" affordance instead of auto-ship.
