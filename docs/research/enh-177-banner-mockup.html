ENH-177 banner — title-from-sessions-index.json mockup

Mockup Filed 2026-05-23 · For ENH-177 re-ship in Sprint 21 · Closes ENH-180
What this is. A faithful render of the banner ENH-177 will show on workspace-switch return, after we fold in the (formerly-ENH-180) detail of reading the session title from Claude's own sessions-index.json. Three states below: Claude's auto-summary, the user's /rename-set custom name, and the UUID fallback for very-new sessions. The mockup is visual-only — no logic. The point is to confirm the experience before code lands.

State A — Claude's auto-summary (the common case)

~/dev/web ~/projects/duo ~/scratch
⏪ This tab had: "Implementing the workspace switcher dropdown" Resume ×
$ # terminal idle — claude not currently running here
~/projects/duo $
State A
Title comes from Claude's own Haiku summary
Claude Code auto-summarizes every session after a few exchanges and writes the result to sessions-index.json under the summary field. The banner reads this directly — no Duo-side LLM call, no extra cost, no transcript pollution.
sessions-index.json § summary
When this fires: any session that's run for more than a few minutes (~95% of return visits).

State B — User-set title via /rename

~/dev/web ~/projects/duo ~/scratch
⏪ This tab had: "Sprint 19 polish wave" Resume ×
$ # terminal idle — claude not currently running here
~/projects/duo $
State B
Title was set by the user via /rename
If the user previously typed /rename Sprint 19 polish wave inside this Claude session, that title takes precedence over Claude's auto-summary. The banner reads the same JSON, just a different field.
sessions-index.json § customName
When this fires: any session the user manually titled. Rare but high-value — these are the sessions the user explicitly considered important.

State C — UUID fallback (very fresh session)

~/dev/web ~/projects/duo ~/scratch
⏪ This tab had Claude session 17d05c98 Resume ×
$ # terminal idle — claude not currently running here
~/projects/duo $
State C
UUID fallback — session was brand-new
When a session has only had one or two exchanges, Claude's summarizer hasn't fired yet — there's no entry in sessions-index.json. We show the first 8 chars of the session UUID. Resume still works (it reads the UUID directly from the per-session JSONL filename). The next time the user comes back, Claude's summary will have landed and the banner shows the real title.
fallback: first 8 chars of session UUID
When this fires: very short sessions — first workspace-switch within minutes of spawning claude. Edge case.

Fallback ladder

The banner's title-rendering is a tiny priority chain — three reads against the same JSON object, with the UUID as the final fallback:

1st customName — user-set via /rename "Sprint 19 polish wave"
2nd summary — Claude's Haiku auto-summary "Implementing the workspace switcher dropdown"
3rd UUID first-8 — derived from JSONL filename "17d05c98"
Why customName wins over summary. If the user explicitly renamed the session, they picked that title intentionally. Claude's summarizer might write something different next time it fires; the user's choice is authoritative.

The JSON shape we're reading

Path: ~/.claude/projects/<encoded-cwd>/sessions-index.json. Encoded-cwd uses Claude's slashes-to-dashes convention (e.g. -Users-geoff-projects-duo for /Users/geoff/projects/duo). The file is a JSON map keyed by session UUID: 

{
  "17d05c98-...-...": {
    "summary": "Implementing the workspace switcher dropdown",
    "customName": null,
    "lastUsed": "2026-05-22T19:14:08.300Z",
    "messageCount": 47,
    "forkedFrom": null
  },
  "a83f4e21-...-...": {
    "summary": "Sprint 19 polish wave — BUG-138 phase 4 cleanup",
    "customName": "Sprint 19 polish wave",
    "lastUsed": "2026-05-21T22:08:11.890Z",
    "messageCount": 112,
    "forkedFrom": null
  }
}

Banner read sequence: load JSON → look up the tab's session UUID → return entry.customName ?? entry.summary ?? uuid.slice(0,8). If the file or entry doesn't exist (very fresh session), fall through straight to the UUID slice.

Interaction unchanged from ENH-177's first build

  • Resume click → write claude --resume <uuid>\n into the PTY. Same wire as ENH-177's original implementation; the title change is display-only.
  • Dismiss (×) → hide the banner for this tab + this workspace-load. Coming back next time still shows it (intentional — easy to dismiss accidentally).
  • Tab focus → banner appears only when the tab is restored from a workspace-switch. Doesn't appear on a cold spawn (no prior session to resume).

What this closes

This mockup is the experience that ENH-180 is no longer needed to produce. The four decisions in the ENH-180 PRD (visibility footprint, title source, quality threshold, idle gate) all asked variations of "how do we generate a title?" — but Claude already does it. We just read.
