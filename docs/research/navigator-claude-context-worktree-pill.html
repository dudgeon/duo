Navigator — Claude-context fill & worktree pill

Status: Accepted (design) Date: 2026-06-17 Scope: navigator sidebar — FilesPane.tsx, FileTree.tsx, ProjectClaudeContext.tsx, worktree hue palette ADR: docs/DECISIONS.md → “Navigator: Claude-context surfacing & worktree indicator”

This artifact locks four design decisions for the navigator. The interactive mockups that led here were iterated separately; this is the consolidated, agreed end-state. Every visual below is the decided treatment, not an option set.

Always-on fill · no click to reveal
DECISION 1

Claude-context highlight = soft background fill

The .claude/ subtree (folder + all descendants) and the top-level CLAUDE.md carry a faint orange background fill (~14% terracotta) wherever they appear in a tree. The fill is the whole signal — no icon badges, no dots.
  • The contiguous .claude/ block reads as one region; CLAUDE.md gets its own fill.
  • This replaces the collapsible “Project Claude context” viewer entirely.
RemovedProject Claude context— the expand/collapse panel is deleted
Why: the context files are always relevant, so a passive, always-visible cue beats a panel users must expand. Lower chrome, zero interaction cost.
Touches: FilesPane.tsx (tree row fill; remove ProjectClaudeContext mount), delete ProjectClaudeContext.tsx.

DECISION 2

Orange is reserved for Claude context

Terracotta/orange means exactly one thing in the navigator: Claude context. Nothing else may use it as a fill, tint, or active-state color.
  • Worktree hue palette excludes orange (projectColorToken) — the git ribbon already tints its background ~13% with the worktree hue, which would otherwise be the same faint orange as the Claude fill.
  • The worktree dropdown current-row highlight is neutral (paper-edge), not accent-soft orange.
  • The branch glyph is rendered neutral (ink), not text-accent.
Why: proven collision — both tints are real, coexist in one sidebar, and land at near-identical strength (swatches at left use the actual color-mix … 13% / 14% formulas). Reserving one hue per meaning is a one-line palette change, not a new mechanism.
Touches: projectColorToken (palette), FileTree.tsx (ribbon tint, dropdown row, branch glyph).

DECISION 3

Worktree indicator = a pill; its menu overlays the tree

The full-width git ribbon is replaced by a rounded, inset pill directly beneath the breadcrumb. Opening it drops a worktree menu seamlessly attached to the pill (shared border, no gap) that overlays / occludes the tree like a standard dropdown.
  • Not a full-width row — a row reads as the parent of the file tree; the worktree is really a property of loop-library, which lives one line up in the breadcrumb.
  • Attached, not detached — the pill and menu share a border (no gap), so it reads as the pill opening, not a separate floating "second pill".
  • Occludes, doesn't reflow — the menu floats over the tree (absolute); the file rows below don't shift down.
Why: correct information architecture (context-of-repo, not parent-of-tree), and a single coherent control whose menu stays attached to its trigger.
Touches: FileTree.tsx (ribbon → inset pill; dropdown → attached absolute overlay).

DECISION 4

Pin button uses the diagonal-pushpin glyph

Replace the PinButton glyph — currently a vertical, outlined thumbtack — with the filled diagonal pushpin from the mockups. More recognizable as “pin / freeze,” reads better at 12–14px.
Heads-up (feeds Decision 2): the pin button's active/pinned state is currently text-accent (orange) — that trips the reservation. See Open items.
Touches: FilesPane.tsx PinButton (glyph path; active-state color).
