The enh-177-banner-mockup.html is the visual companion — open it in Duo's browser pane via duo open to flip through the 7 states. The Notion mirror embeds the PNG render for phone-side review.

1 · Why this exists

Workspace switch tears down terminal tabs and re-spawns them on restore — Claude sessions running inside those tabs don't survive. The user loses their working context with no breadcrumb back to it. Owner directive (2026-05-23):

"When a terminal tab had an active claude session in it, and the user switches to a different workspace and comes back, their claude session appears to be lost. I want us to know (e.g. via workspace autosave metadata) when a given terminal tab last had an active claude session, ideally an identifier for that claude session, such that on session restart we can either run claude resume {session}, or remind the user that they can (with a non-annoying banner)."

The original ENH-177 build (f351719) shipped the banner mechanism but was reverted at 49f4644 before the v0.7.7 cut for re-ship after a proper owner walk. Sprint 21 re-ships it bundled with ENH-181 (the inline-rename + collapse-toggle behaviors that emerged from the v0.7.8 design conversation), and absorbs the closed ENH-180 (auto-rename via /rename — killed because Claude Code already auto-summarizes).

4 · Owner-locked decisions

All decisions below are locked. The accompanying rationale captures why we landed where we did so future-us doesn't re-litigate.

D1 · Banner trigger — workspace switch only?
✅ Yes. Banner surfaces only when a workspace-switch restore detects a prior claude session for this tab. Not on Duo cold-start (would be too noisy across many sessions over time).
Owner spec 2026-05-23. The use case is the specific "I just switched workspaces" friction — not a general "you have old sessions" reminder.
D2 · Title source — what does the banner say?
✅ Read ~/.claude/projects/<encoded-cwd>/sessions-index.json for the matching session ID. Precedence: customName > summary > short(UUID). Re-read on file change (debounced) so claude's own auto-summary refresh and our /rename write both propagate live.
Owner observation killed ENH-180 (auto-rename via Duo-side Haiku). Claude Code already writes a Haiku summary after ~3 exchanges. We just read it. Zero schema coupling on our side.
D3 · Manual rename mechanism — direct file write or PTY injection?
✅ Path 2: PTY injection. Duo writes \r/rename <title>\n to the live claude PTY. Claude processes the slash command and updates sessions-index.json § customName itself.
Trade-off accepted: 2-line transcript footprint per rename (the /rename command line + claude's confirmation). Benefit: zero schema coupling — claude owns the write, our injection survives any sessions-index.json format migration. Direct file write would couple us to a private file format. Empirically verified during the v0.7.8 design conversation.
D4 · Edit gating — when is rename allowed?
✅ Only when claudePresence === 'claude' in the tab. When claude is not alive in the tab, the title shows non-editable (cursor: not-allowed + tooltip explaining).
Owner directive 2026-05-23: "if needed we can limit to only when Claude is active." Required by mechanism — without a live PTY, the inject has nowhere to land. Future ENH could allow rename via direct write when claude is dead, but ships separately.
D5 · Default state after workspace switch — banner shown or marker only?
✅ Collapsed marker on the tab (a small ⏪ chip). Banner hidden by default. Tapping the tab toggles between the two.
Owner directive 2026-05-23: "bundle in a collapse function: tapping on tab exposes it, hides the description." The banner is high-signal but visually heavy; the marker is the always-on equivalent of "you have a session you can resume here." Tap-to-toggle keeps the discoverability without the noise.
D6 · Esc handling — cancel-edit or dismiss-banner?
✅ Esc cancels mid-edit only. Reverts the title to its prior value. Does NOT dismiss the banner. (Banner dismissal stays on the × button.)
Owner directive 2026-05-23: "Esc while editing name should cancel/revert." Standard contentEditable UX; matches most rename-in-place flows.
D7 · ENH-180 disposition — ship auto-rename via PTY?
✅ Closed. Folded into ENH-177 as "banner reads sessions-index.json." The PTY /rename mechanism survives in ENH-181 as the user-driven case only.
Owner observation 2026-05-23: Claude Code already writes Haiku-generated summaries to sessions-index.json automatically. Duo doesn't need its own title generator. Closes a 20-line read instead of a 200-line write+filter+cost-management feature. ENH-180 PRD preserved with closure banner in case a v2 ever revisits.

6 · Mechanism empirics (locked, don't re-research)

ApproachCostLatencyPersists?Verdict
claude -p '/rename X' n/a n/a n/a Rejected Returns "isn't available in this environment" — slash commands are TUI-only.
--name on --resume $0.73/call multi-second Not visibly Rejected Expensive (Opus default + 117K cache-token reload). Title doesn't visibly persist to sessions-index.
Direct write to sessions-index.json $0 ~0s Yes Rejected Schema-coupled. Breaks if Claude Code changes the file format.
Write \r/rename <title>\n to live PTY $0 ~0s Yes ✅ Chosen Persists to customName. Visible in /resume picker + terminal title + the banner. Zero schema coupling. The \r prefix is critical — verified empirically; just /rename\n doesn't always commit if there's pending input on the PTY line.

7 · Risk + edge cases

Risk: Claude died between trigger and rename click.
Mitigation: D4's claudePresence === 'claude' gating. Title becomes non-editable when claude is absent; tooltip explains why. Pencil glyph and dashed underline disappear.
Risk: sessions-index.json missing or unreadable (very fresh session, permissions issue, custom Claude Code install path).
Mitigation: Fallback ladder. Title falls through to short(UUID) if neither customName nor summary is available. Renamed sessions appear with their UUID prefix until claude generates a summary or user runs /rename.
Risk: Multiple claude sessions in the same cwd; banner shows the wrong one.
Mitigation: ENH-177's detectLatestClaudeSession picks the newest .jsonl by mtime. Per-tab capture at autosave time means the banner shows the specific session that WAS running in this terminal tab, not the cwd's most-recent session globally.
Risk: User mid-edit when focus drifts to another app (e.g. iMessage notification click).
Mitigation: Click-outside also commits (consistent with most contentEditable UX). Esc explicitly cancels. No "draft in limbo" state.
Risk: User types /rename manually in the claude transcript while edit mode is open in the banner.
Mitigation: Banner re-reads sessions-index.json on file change. The user-typed rename takes effect immediately; the banner picks up the new title. If edit mode is open at that moment, Return-to-commit would overwrite the manual rename, but that's the user's stated intent (they're typing in the banner). No data loss path.
Risk: The \r prefix collides with some shell mid-state where another character is mid-input.
Mitigation: Verified empirically during v0.7.8 design conversation; \r reliably commits any pending input then submits the /rename line. Edge case for a paste-in-progress is theoretical and would still produce a single recoverable line in the transcript.

9 · Acceptance criteria

  1. Workspace switch → return: affected terminal tab shows ⏪ marker chip.
  2. Tap tab → banner expands with title from sessions-index.json (Haiku summary or customName).
  3. Banner title click → contentEditable + accent border (only when claudePresence === 'claude').
  4. Type new title → Return → /rename lands in claude transcript → sessions-index.json § customName updates → banner re-renders.
  5. Esc cancels mid-edit; click-outside commits.
  6. Tap tab a second time → banner collapses to marker.
  7. × dismisses banner for the current tab-session only.
  8. CLI parity: duo session rename / collapse / expand work as documented.
  9. No regression: workspace switch baseline behavior (tab restore, cwd preservation) unchanged.
  10. No regression: terminal-tab right-click menu, ⌘W close-tab, ⌘Z reopen-closed-tab unchanged.

10 · Out of scope (deferred)

  • Rename when claude is dead — D4 gates on live presence. Direct file write would allow rename-when-dead but couples us to the schema. Defer until owner sees the friction.
  • Multiple sessions per tab UI — banner shows the single most-recent .jsonl by mtime. Picking among multiple priors is a future ENH.
  • Cross-tab rename propagation — same session ID in multiple Duo windows would show separate banners. Live fs.watchFile means a rename in one window updates the others; race conditions on simultaneous edits in two banners are theoretical (and the second commit wins, no data loss).
  • Resume-by-search — picking among ALL prior sessions for a cwd (not just the most-recent). This is what claude /resume already does in-TUI; Duo doesn't duplicate it.
  • Rename keyboard shortcut — no ⌘E-style chord for "enter edit mode." Click is the only path. Owner can ask for a chord post-ship if needed.
