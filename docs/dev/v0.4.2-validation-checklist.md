# v0.4.2 validation checklist

> Walk this checklist after the v0.4.2 cut lands on your machine.
> Tracks the auto-update path (Stage 21c Phase 1), the session-restore
> path (Stage 21c Phase 2), and a regression smoke against the rest of
> the app.

**Cut details:**
- Tag: `v0.4.2`
- Date: 2026-04-27
- Release: <https://github.com/dudgeon/duo/releases/tag/v0.4.2>
- Commit: `ccd1e84` on `main`

**Pre-flight assumption:** you currently have **v0.4.1** installed in
`/Applications/Duo.app` from the previous cut. If you have an older
version (v0.4.0 or earlier — those were unsigned), auto-update won't
work and you'll need a manual install of v0.4.2 from the GH release.
Skip Step 1 in that case and resume at Step 2.

## Step 1 — Auto-update v0.4.1 → v0.4.2 (Stage 21c Phase 1)

This is the headline new capability. The first time anyone hits this
path is right now, with you.

- [ ] **1.1** Quit any running Duo (cmd-Q).
- [ ] **1.2** Double-click `/Applications/Duo.app` to launch v0.4.1.
  - Expected: app boots cleanly to the standard 3-column layout.
  - Tab strip shows whatever you had at last quit (terminal + browser
    tabs may be empty since v0.4.1 doesn't have session restore yet —
    Step 2 covers v0.4.2 onwards).
- [ ] **1.3** Within ~15-30 seconds of boot, watch for the auto-update
  flow:
  - Console-only initially: `[auto-updater] checking-for-update`
    fires (you won't see this in the UI).
  - Then: `[auto-updater] update-available: 0.4.2`
  - Then: `[auto-updater] download X% (Y/Z bytes)` repeatedly
  - Then: `[auto-updater] update-downloaded: 0.4.2`
  - Then: **macOS native dialog appears** —
    > "A new version of Duo has been downloaded. Restart the
    > application to apply the updates."
    > *[Later]*  *[Restart]*
- [ ] **1.4** Click **Restart**.
  - Expected: Duo quits, brief pause (~2-5 seconds while the new
    .app replaces the old in `/Applications`), then re-launches as
    v0.4.2.
- [ ] **1.5** Confirm v0.4.2 is running:
  - Open the FAQ tab (default-pinned). Scroll to "What's new" — top
    article should be the v0.4.2 entry ("auto-update + session
    restore").
  - Or from a terminal tab: `duo --version` should return `0.4.2`.

**If 1.3's native dialog never appears:**
- Check Console.app filtered to "Duo" — auto-updater logs to main-
  process console which surfaces there. Look for `[auto-updater]`
  lines. Common failure modes:
  - `update-not-available` → cache disagreement; quit Duo, delete
    `~/.claude/duo/update-check.json`, relaunch.
  - `error: <something about signature>` → notarization didn't chain
    correctly. Surface as a bug.
  - No `[auto-updater]` lines at all → wiring didn't take. Surface
    as a bug.

**If 1.4 hangs after Restart click:**
- Wait 30 seconds. macOS's app-replacement step can stall briefly.
- If still hung, force-quit and manually launch from /Applications.
  Whatever's there should be v0.4.2 (the auto-installer wrote the
  new .app before quitting the old).

## Step 2 — Session restore (Stage 21c Phase 2 — issue #24)

Closes issue #24. This is the daily-driver ergonomic that should now
"just work" — open multiple tabs, quit, reopen, find them again.

- [ ] **2.1** With Duo running v0.4.2, open multiple tabs of each
  type:
  - **Terminal tabs:** create at least 2. Try one shell tab and one
    claude tab (`+` button defaults to claude; `>` button opens shell).
    `cd` somewhere recognizable in each (e.g. `cd /tmp` in one,
    `cd ~/Documents/GitHub/duo` in another).
  - **Browser tabs:** open at least 2. Navigate one to a
    recognizable URL (e.g. `https://example.com`); leave the other
    on the FAQ default.
  - **File tabs:** open at least 1 markdown or HTML file from the
    navigator. Type something into it (don't save — we want to
    verify saved state, not in-memory edits).
- [ ] **2.2** Note which tab is active in the WorkingPane (browser /
  file). This active selection should also restore.
- [ ] **2.3** Confirm session-state.json was created:
  ```bash
  cat ~/.claude/duo/session-state.json | head
  ```
  Should show your terminal CWDs, browser URLs, file paths.
- [ ] **2.4** Quit Duo (cmd-Q). **Important: clean quit, not
  force-quit** — a force-quit would skip the
  before-quit flush and could lose ~500ms of edits (still works, just
  less reliable).
- [ ] **2.5** Reopen Duo.
- [ ] **2.6** Verify each tab type came back:
  - **Terminal tabs:** same count, same kinds (shell vs claude),
    same CWDs (each terminal's first prompt should reflect the cwd
    you set in 2.1, not your `$HOME`).
  - **Browser tabs:** same count, same URLs. Note: the browser tabs
    re-load fresh on launch (no DOM snapshot), so any scroll
    position / form state won't survive — that's expected.
  - **File tabs:** same count, same files open. Buffer reloads from
    disk — your unsaved edits from 2.1 are GONE (also expected —
    matches macOS native-app norms; no autosave layer in v0.4.2).
  - **Active selection:** the same tab is highlighted that you had
    selected in 2.2.
  - **Pinned tabs:** still pinned (Stage 24 already shipped this).

**If any tab type doesn't restore:**
- Check the file:
  ```bash
  cat ~/.claude/duo/session-state.json
  ```
- The relevant field (`terminals`, `browserTabs`, `fileTabs`) should
  have an array reflecting what you had open. If the array is empty
  but you definitely had tabs open, the save effect didn't fire
  before quit — surface as a bug.
- If the array is correct but the restore didn't happen on launch,
  the load effect failed — surface as a bug with the file contents.

## Step 3 — Regression smoke (does anything else break?)

Quick walk through the other surfaces — don't dwell, just confirm
nothing's outright broken by the v0.4.2 changes.

- [ ] **3.1 Terminal pane.** Open a new shell tab. Type `pwd` —
  should print `$HOME` or wherever you were last. Type `ls` — should
  show files. Cmd-T from terminal focus opens a new claude tab. Cmd-W
  closes the active tab.
- [ ] **3.2 Browser pane.** Open a new browser tab via `+ ⌥-click`
  (alt-click on the new-tab button). Navigate to a URL via the
  address bar. Click forward / back arrows. Cmd-R reloads.
- [ ] **3.3 File navigator.** Navigate to a folder via the breadcrumb.
  Click on a `.md` file → opens in editor tab. Click on an `.html`
  file (any) → opens in canvas tab. Pinned files (FAQ + What Duo Does)
  show with pin glyph in the tab strip and sort to leftmost.
- [ ] **3.4 Markdown editor.** ⌘N → new-file interstitial. Type a name
  ending in `.md`. Press ↵ → editor opens. Type some markdown. ⌘S
  saves; the dirty-dot disappears from the tab title.
- [ ] **3.5 HTML canvas.** ⌘N → new-file interstitial. Type a name
  ending in `.html`. Editor opens with the smart-blank overlay.
  Click into it, type something. Save (⌘S).
- [ ] **3.6 Keyboard shortcuts.** From any focus context, ⌘T (new
  claude tab), ⌘N (new file), ⌘W (close tab), ⌘B (toggle browser),
  ⌘\` (toggle terminal column), ⌘L (focus address bar). All should
  fire. The preventative-architecture from v0.3.0 ensures these work
  from canvas / editor focus too.
- [ ] **3.7 Theme toggle.** Light / Dark / System cycle via the
  toggle. System mode follows the OS appearance.
- [ ] **3.8 Stage 22 dual-pane navigator.** Top pane "Your Claude
  settings" should show `~/.claude/CLAUDE.md` + `skills/` +
  `agents/`. Toggle "Show all" → reveals the rest of `~/.claude/`.
  Bottom pane shows the project tree.
- [ ] **3.9 GitHub Releases update banner.** This is the v0.4.0
  banner (now informational/fallback). It should NOT show "Duo v0.4.2
  is available" because you're running v0.4.2 now. If it's stale
  (showing v0.4.2 even though you're on v0.4.2), delete
  `~/.claude/duo/update-check.json` and relaunch.
- [ ] **3.10 `duo` CLI.** From a terminal: `duo --version` returns
  `0.4.2`. `duo doctor` reports a clean transport (Unix socket
  primary). `duo external https://capitalone.com` triggers the
  Stage 25 banner ("Sent capitalone.com to your default browser").

## Known limitations at v0.4.2 (don't report these as bugs)

- **Live `cd` movement isn't tracked.** Only the SPAWN cwd persists
  for terminal tabs. If you `cd` somewhere else mid-session, that
  movement won't restore. Future enhancement; see issue #24
  comments.
- **Unsaved file-tab edits are LOST at quit.** No autosave layer.
  Matches macOS native-app norms.
- **Browser scroll / form state isn't captured.** WebContentsView has
  no snapshot API; restore re-navigates fresh.
- **Browser history persistence (issue #27) deferred.** Address-bar
  autocomplete still suggests only currently-open tabs. Stage 21c
  Phase 3 — ships into v0.4.3 or v0.5.0.
- **Stage 21e (fork-friendly architecture) not yet shipped.** Forkers
  today still patch seven files by hand; v0.5.0 will close that.
  See `docs/HOW-TO-FORK.md` for the layered fork modes.
