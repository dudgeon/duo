Cosmetic findings — worth filing

BUG-009 residual. The waitForPtyReady helper waits for the shell's first PTY data event before writing the post-spawn payload. But the shell may emit something before drawing PS1 (a color escape, a working-dir notice, etc.). When that happens, claude\n writes too early and the literal claude renders on a bare line above the prompt. End-to-end claude DOES launch (vs. the original bug where it didn't), but it's visually noisy. Candidate fix: prompt-detector regex (look for trailing % , $ , # , > ) instead of "first data" trigger.
