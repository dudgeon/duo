## New modules (Appendix B)

### `electron/cache-key.ts`

Generic per-window-keyed snapshot cache (Map<windowId,T>) that replaces the 12 identity-free module-global `let`/`const` caches in main.ts. Pure node-env (imports only the WindowRegistry TYPE; zero Electron), so the keying contract is unit-testable without mounting Electron — mirrors safe-send.ts / window-resolve.ts. The BrowserWindow.fromWebContents(event.sender)?.id resolution stays in main.ts and is passed in as a plain number. Shared by the caches cluster (items 1+2), item-8 activeTerminalId/tabsThatHostedClaude, and the item-12 projectsState fan-out.

**exports:** class WindowKeyedCache<T> { set(windowId, value) [WRITER]; get(windowId): T|undefined; getOrDefault(windowId|undefined): T; getDefault(registry): T; delete(windowId); size() }, function defaultWindowId(registry): number | undefined  (registry.only()?.id — inherits the N>1 THROW)

### `electron/reqid-validate.ts`

Sender-validated reqId reply resolver for the 12 dispatch/reply families. Maps stay global (reqIds are random + per-family-prefixed) but the target windowId is recorded at dispatch and any reply whose event.sender window id != the recorded target is DROPPED (entry left pending so the legitimate reply can still arrive; timeout cleans up). Pure node-env (zero Electron import); the BrowserWindow.fromWebContents(event.sender)?.id mapping stays in main.ts and is passed in pre-resolved — same split as resolveBySender(registry, id).

**exports:** interface PendingEntry<R> { targetWindowId: number; resolve: (res: R) => void }, class PendingRegistry<R> { set(reqId, targetWindowId, resolve); deliver(reqId, senderWindowId|undefined, res): boolean; delete(reqId); has(reqId); size }

### `electron/eventsink-route.ts`

Pure, Electron-free router for SocketServer's ambient cues (browser:focus-gained supplemental push + claude:read-selection read-glow): given the addressed window id + the registry, send the cue to THAT window via resolveBySender, falling back to the sole window (resolveDefault/only()) when the id is absent or stale. The eventsink counterpart of safe-send.ts/window-resolve.ts, isolated so socket-server.ts stays Electron-free (it only learns an opaque number). NEVER getFocusedWindow.

**exports:** function routeAmbientCue(registry, windowId: number | undefined, channel: string, payload: unknown): void

### `core/pty-owner.ts`

Pure (Electron-free) owner-routing + lifecycle logic for PtyManager: resolve a session's owning window (with sole-window fallback — the cold-start drop guard), dispose sessions scoped to one window (workspace-swap path), and list cwd-matched ids filtered by owner (C9 positional-match fix). Mirrors core/event-sink.ts + electron/window-resolve.ts being pure node-env so the multi-window PTY contract is unit-testable without node-pty or Electron. WindowLike is imported TYPE-ONLY (or redeclared structurally) to avoid an electron→core import edge.

**exports:** function routeSend(sessions, sessionId, resolveOwner, fallback): WindowLike | undefined, function disposeForWindow(sessions, windowId): string[], function listIdsByCwdOwned(sessions, cwd, ownerWindowId?): string[]

### `electron/window-registry.ts (EXTENDED, not new)`

The P2 WindowContext interface gains two optional per-window fields in P3-S8a — the home for item-10's active-workspace pointer and item-8's presence probe. activeWorkspace?: ActiveWorkspace|null (import type from shared/types — plain {path,name}, zero Electron; persistence stays P4); presence?: unknown (the per-window ClaudePresenceProbe slot, kept unknown so the registry imports zero Electron/core).
