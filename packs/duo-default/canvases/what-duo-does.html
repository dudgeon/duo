What Duo does

A plain-English reference of every substantial thing Duo can do, with a use case and the way to invoke it. Many items have both a UI path and a duo CLI command — the CLI is what you ask Claude to use when you want the agent to drive Duo for you. Numbered for quick reference: "see item 23."

Editing files

Markdown documents, HTML canvases, and the shared toolbar conventions.

1

Edit markdown files

Open any .md file as a rich editor in the working pane — formatting toolbar, markdown shortcuts on typing, autosave.

UIClick the file in the navigator. CLIduo edit <path.md>

2

Markdown shortcuts on typing

Type # to make a heading, - / * / + for a bullet (the marker character is preserved visually — - renders as an en-dash, + as a plus, * as the default disc), **bold** for bold, 1. for a numbered list, > for a quote, --- for a divider, ``` for a code block. Press Enter twice on an empty line inside a bullet, ordered list, or blockquote to exit it. Works in both the markdown editor and the HTML canvas. v0.6.5+ for the marker-passthrough + blockquote double-Enter exit.

UIJust type. The shortcut fires on the space or Enter that ends the trigger.

3

Use the formatting toolbar

Heading picker, B/I/U/S, link picker, bullet / ordered / task lists, blockquote, code block, horizontal rule, table insert, undo/redo, save. Same toolbar in the markdown editor and the HTML canvas.

UIClick a button at the top of the editor.

4

Edit tables in place

Insert a table with the table button. When the cursor is in a cell, a contextual second toolbar row appears: add row above/below, add column left/right, delete row, delete column, toggle header row, delete table.

UIClick into a cell.

5

Copy a code block

Hover any <pre> in the markdown editor or HTML canvas — a Copy button appears top-right. Click it; the code text lands on your clipboard.

UIHover the code block. v0.5.1+

6

Find text in the markdown editor

⌘F opens a find bar above the prose. Type a query; matches highlight inline with a counter (3/47). ↓ / ↑ (or ▼ / ▲ buttons) navigate to the next/prev match with a smooth scroll. ⎋ closes. Case-sensitive toggle (Aa) is a click. Works in dark mode without the previous contrast issue.

UI⌘F. v0.5.3+

7

Indent / outdent list items

Inside a bullet, ordered, or task list, ⌘] indents the current item (sinks it into a sub-list); ⌘[ outdents (lifts it back). Outside a list the chord no-ops. Familiar from Obsidian / Bear / Notion. Works in both the markdown editor and the HTML canvas (canvas parity shipped v0.6.5; markdown editor since v0.5.3). Tab / Shift-Tab also indent / outdent inside list items in both surfaces.

UI⌘] / ⌘[ (or Tab / Shift-Tab) inside any list item.

8

Tell the agent to scroll the editor

When Claude is working with you on a long doc, this gets it to land you both at the same spot without you having to scroll-and-search. --heading matches by heading text; --line by 1-indexed source line; --anchor by GitHub-slug (so --anchor "bug-038" matches the heading ### BUG-038: …). Response includes matched_heading so the agent can confirm it landed on the right entry.

CLIduo doc goto [<path>] --heading "X" | --line N | --anchor "Y" · v0.5.3+

9

Have the agent search the editor's live buffer

Read-only counterpart to duo doc goto. The agent gets back the matching lines + counts without scrolling you anywhere. Use when the agent needs to know "is this term in the doc, and where?" without disrupting your view.

CLIduo doc find "<query>" [<path>] [--case-sensitive] · v0.5.3+

10

Right-click for the usual context menu

Right-click anywhere in the markdown editor, HTML canvas, or browser pane to get Cut / Copy / Paste / Select All / Look Up "selection" / Spell-check suggestions. In dev builds you also get Inspect Element. Browser tabs get the link / image variants too (Copy Link, Save Image As, etc.) when you right-click a link or image.

UIRight-click. v0.5.4+

11

Copy without formatting

When you copy from a rich source, Duo's "Copy as Plain Text" gives you just the text — no markdown marks, no HTML tags, no bold/italic. Pastes cleanly into terminals, plain-text fields, anywhere you don't want formatting following along.

UIRight-click selected text → "Copy as Plain Text", or ⌘⌥C from the keyboard. v0.5.4+

12

Edit an HTML file as a live canvas

Open any .html file as a rendered, editable canvas — what you see is what gets saved. Same toolbar as the markdown editor, plus markdown shortcuts on typing.

UIClick the file in the navigator. CLIduo edit <path.html>

13

Create a new file

Make a new markdown file or HTML canvas from a filename interstitial — type the name, hit Enter, start typing.

UIClick + on the working-pane tab strip. Type a filename ending in .md or .html. CLIduo html new <path.html>

14

Add comments to a document — markdown editor or HTML canvas

Both surfaces have the same comment UX. Select text, then any of: press ⌘⌥M (Google Docs parity), right-click and pick "Comment", or click the 💬 button on the toolbar. Markdown comments persist inline as CriticMarkup ({==anchor==}{>>id|author|ts|body<<}) so they travel with the file — visible to the agent, git-diffable, no sidecar needed. HTML canvas still uses a sidecar. The commented text shows a soft orange highlight. Click rail thread → anchor strengthens; click anchored text → rail thread focuses. Resolve a thread and the body highlight disappears. v0.7.3: comments + tracked changes now share a single annotation rail with items interleaved by document position (was two rails side-by-side eating ~560px of width). Replies to existing threads no longer need --anchor — pass --reply-to <c-id> alone and the body lands inside the parent's thread.

UISelect text → ⌘⌥M / right-click "Comment" / toolbar 💬 → write → ⌘+Enter. CLI (new comment)duo doc comment <file> --anchor "<text>" --body "…"CLI (reply)duo doc comment <file> --reply-to <c-id> --body "…"CLI (canvas)duo html comment --id <duo-id> --body "…"

15

See what the agent just changed

When Claude pushes an edit (markdown editor or HTML canvas), the changed region paints yellow and fades to transparent over ~6 seconds. Reopening a file within the freshness window repaints recent edits — useful for catching up on background agent work.

UIWatch the canvas after running an agent edit.

16

Get warned before an agent overwrites your unsaved edits

If you have unsaved changes and the agent tries to write the same file, a banner appears with a preview of the agent's intended write and Apply / Decline buttons. Decline returns an error to the agent saying you declined.

UIRead the banner, choose Apply or Decline.

17

Paste an image into a markdown doc or canvas — portable across machines

⌘V or drag-drop an image into the markdown editor or HTML canvas — Duo saves it alongside the active doc as image-<YYYYMMDD-HHMMSS>-<hash>.<ext> and inserts it inline. Supported: PNG, JPG, GIF, WEBP, SVG, BMP, TIFF. Pre-v0.6.10 you had to save-to-Desktop → drag-to-Finder → markdown-link-by-hand. Pre-v0.6.11 the markdown source carried ![](blob:...) URLs that died on doc reload. v0.6.11+: the source carries ![](image-<stamp>.png) (relative filename) and a NodeView resolves the path at mount time — files survive reload, git commit, copying to another machine. Untitled buffers warn-and-decline (save the doc first so we know where to put the image).

UI⌘V (clipboard image) or drag from Finder. CLIduo image insert <path> [--alt "alt text"] (works against the active markdown editor OR HTML canvas — v0.6.11 closed the canvas-side parity gap).

18

View images with a real toolbar

Open any image (PNG, JPG, GIF, WEBP, SVG) in the working pane and you get a toolbar over the image area: zoom in/out (+/−, ⌘/⌃-wheel), click-toggle fit/manual, fit-to-window, 1:1 actual size, copy-image, dimensions + file-size readout (e.g. "1440 × 900 · 312 KB"). Drag to pan when zoomed past the container.

UIDouble-click an image in the file navigator or open via duo edit <path-to-image>. Right-click anywhere on the image for the native menu (Copy image / Copy path / Open in default app / Reveal in Finder / Fit / 1:1).

19

View raw source for the active editor or canvas (read-only)

Sometimes you want to see what's ACTUALLY in the file — markdown source (with frontmatter) for the editor, pretty-printed HTML (with data-duo-id attrs and the canonical attribute order) for the canvas. Useful for verifying what a paste / agent edit / autosave actually wrote, or for grabbing a chunk to share. v0.6.11 shipped v1 as a centered modal; v0.6.12+ reshapes it as a panel-fill — the source view replaces the prose / canvas area in the same column / dimensions, with three triggers (chord, View menu entry, tab right-click) all hitting the same toggle.

Keyboard⌘⌥V on the active editor or canvas opens (and re-closes) the source panel. UIView → View source menu, or tab right-click → "View source" (with a display-only ⌘⌥V accelerator label for muscle-memory training). Done button / Esc dismiss. Read-only — editable view-source (CodeMirror with bidi sync) intentionally deferred per owner entry-gate pick.

20

Open a JSON or YAML file as a viewer-editor

PMs (and everyone else) deal with API responses, configs, webhook payloads, manifests, docker-compose files. Pre-v0.6.12 they fell through to the "unknown file" preview. v0.6.12+ ships a Tier 3 collapsible tree (with click-to-edit values, hover-to-copy, type color-coding) for .json / .jsonl / .har / .webmanifest / .yml / .yaml. Single tab kind for both formats — format implicit from path extension. The toolbar Edit button flips to a CodeMirror raw-text editor with JSON/YAML syntax highlighting + inline error markers (red gutter dot + squiggly underline at the parser's position + hover tooltip with the full message). Source-mode Save button force-saves + flips back to tree if parse succeeds; invalid input shows a three-layer error banner (friendly summary → pattern-matched hint like "Did you forget a closing }?" → faded raw V8 / js-yaml line-column message). Revert button restores the last-saved buffer. Files >1 MB drop to a read-only source-only view (tree render cost is prohibitive at scale). Autosave on debounce (800ms) matching the markdown editor.

UIDouble-click a JSON / YAML file in the navigator, or use duo edit foo.json. Tree mode is the default; click a value to edit it; click Edit ↔ Save to flip between tree and raw-text. LimitationYAML round-trip is content-only — comments + anchor names are stripped on save. Pure-content YAML preserves exactly.

21

Suggest changes in a markdown doc (track-changes)

Toggle the pencil icon in the toolbar (or press ⌘⌥T) to enter Suggesting mode. With Suggesting ON, typing wraps your new text as a CriticMarkup insertion ({++…++}) and Backspace/Delete wraps as a deletion ({--…--}) instead of removing characters. A bulk banner above the body shows "N suggestions · Accept all · Reject all"; the per-suggestion rail on the right has ✓/✗ buttons + All/Mine/Agent/Others filter chips so a reviewer can sweep by author. The mode persists per-doc in the sidecar, so you can leave a file in Suggesting=on for the next session. The agent participates via duo doc insert / duo doc delete / duo doc substitute / duo doc highlight / duo doc accept / duo doc reject; everything round-trips through the same CriticMarkup tokens on disk.

UIClick the pencil icon in the toolbar (or ⌘⌥T) → type / Backspace as usual. CLIduo author "Geoff" sets your identity; duo doc insert <file> --after "X" --text "..." / duo doc highlight <file> --text "X" (v0.7.2 — wrap "X" as {==X==} highlight) / duo doc accept <file> --match "X" etc. for agent-driven flows.

22

See and edit YAML frontmatter as Properties

Every .md with a frontmatter block shows a Properties panel above the prose. Structured key:value rows render the parsed YAML; click the chevron to collapse (state persists per-doc); click "Edit raw" to flip to a YAML textarea with live parse-error feedback. Files without frontmatter show a "+ Add properties" call-to-action. Closes the architectural gap where the markdown editor used to hide the YAML block entirely.

UIOpen any .md with frontmatter — panel mounts automatically. Click "Edit raw" for free-form YAML edits.

16

Edits from disk or an agent show up live

When something outside the editor changes a file you have open — an agent, another editor, git, a cloud sync — Duo reloads it in place and highlights what changed (added text washed, removed lines ticked in the margin) until your next keystroke. If you had unsaved edits, you get a "changed on disk — reload or keep mine" choice instead of silent loss. The same live refresh now covers the JSON/YAML, image, and PDF viewers. v0.9.0 rebuilt this on one shared reconciliation core, ending a long tail of false-positive "changed on disk" banners.

Automatic — nothing to invoke. Agents should edit open files through Duo so the change shows live: duo doc edit <file> --find … --replace …, duo json set|merge <file> …, or the duo html verbs; duo status lists what's open.

Browsing the web

An embedded Chromium pane. Tabs, address bar, the same shortcuts you'd expect.

23

Open a browser tab

A real Chromium tab inside Duo. Logged-in sessions persist between launches. Local file:// tabs auto-reload when the underlying file mutates (v0.7.1+) — so an agent editing a playground via the CLI shows the result without you hitting ⌘R.

UIClick > on the working pane's split-button (right of the tab strip), or ⌘T while the browser pane has focus. CLIduo open <url>

24

Reopen the last-closed browser tab

Closed something by accident? Same gesture you use in Chrome.

UI⌘⇧T while the browser pane has focus. (From any other focus, ⌘⇧T spawns a new Claude tab.) v0.5.1+

25

Jump to the address bar

Type a URL or search term without reaching for the mouse. Start typing → suggestions from your visited-history match as you type (sorted by recency × visits).

UI⌘L from anywhere in the working pane. Arrow keys to pick a suggestion; Enter commits.

26

Navigate the browser

Back, forward, reload — useful when you're asking Claude to drive a multi-step web task.

UIBrowser pane controls. CLIduo back · duo forward · duo reload

27

Open a link in your real browser

Off-host or work-restricted URLs (SSO, internal sites, bookmarks-only) belong in your default browser, not Duo's embedded Chromium. Duo will route them out automatically when the domain is on the external list.

CLIduo external <url> — or just paste a URL into a Duo terminal and let Claude decide.

28

Find text on the current page

⌘F opens a find bar above the address row when the browser pane is active. Matches highlight on the page; the bar shows "n/m" so you know where you are. Enter or ⌘G goes to the next match; ⇧Enter or ⌘⇧F goes back. ⎋ closes and clears highlights.

UI⌘F (browser pane focused). v0.5.4+

29

Inspect an element on the page and send it to Claude

v0.7.0: ⌘⇧C (or duo inspect) puts the browser pane into element-inspect mode. Hover any element on the page to outline it; click to freeze the selection and pin a "Send → agent" pill anchored to the element. ⌘D (or click the pill) ships the element's snapshot — tag name, computed selector, inner text, attributes, page title — to your active Claude terminal. ESC unfreezes without shipping. Three-state machine: idle → hovering → frozen → ship-and-exit. Same egress as text selection's Send → agent pill.

UI⌘⇧C → hover → click to freeze → ⌘D to ship · or duo inspect from the CLI to toggle.

30

Send Claude to a URL without losing your current tab

v0.7.7: when an agent runs duo navigate <url>, it opens the URL in a new browser tab or focuses an existing matching one (match strips hash + trailing slash). Your active tab stays where you left it. Useful when Claude is doing a side-investigation and you don't want to lose the docs you were reading. The renderer's address bar keeps its older reuse-active-tab behavior — that's an explicit user override.

CLIduo navigate <url> (returns {ok, url, title, reused} — reused: true means a matching tab existed).

31

Switch what the embedded browser is allowed to render

v0.7.8: Duo's embedded browser ships with three URL-filter modes. local-only (new default for fresh installs) only renders file:// / localhost / 127.0.0.1 / [::1]; every other URL pops your system browser. filtered preserves the legacy behavior — domains listed in ~/.claude/duo/external-domains.json pop the system browser, the rest render in Duo. unfiltered is the debug escape hatch — any URL renders inside Duo. Switching to unfiltered requires --i-understand on the CLI to bypass an IT-policy warning, because some enterprise environments restrict agent-driven browsing on the open internet.

CLIduo browser-mode reads the current mode. duo browser-mode local-only / filtered sets it. duo browser-mode unfiltered --i-understand sets the debug mode after the IT-warning gate.

36

See and clear navigator selection easily

37

Open a file from Finder into Duo

Duo registers as a macOS Open With candidate for .md and .html files. Right-click any markdown or HTML file in Finder → Open With → Duo, and the file lands in the working pane via the same verb-driven routing as duo open (markdown → editor; HTML → browser pane, interactive). Set Duo as the default for an extension via Get Info → Open With → Change All. Cold-start is supported — opening a file from Finder while Duo is closed launches the app and routes the file once the renderer mounts. v0.6.5+ (signed DMG only)

UIRight-click a file in Finder → Open With → Duo, or set Duo as default for the extension.

38

See git status at a glance in the Navigator

v0.7.0: when the Navigator's cwd is inside a git repo, a slim ribbon at the top of the tree shows the branch + dirty / ahead / behind counts (`main · 3 modified · 2 ahead`). Right-click the ribbon for repo-level menu items. When the cwd contains MULTIPLE child folders that are repo roots (e.g. `~/Documents/GitHub` with `duo/`, `figma-cli-skill/`, etc.), each child gets a small right-aligned ⎇ Lucide git-branch icon — hover the icon to reveal the same chip in a popover below the row. Icon color reflects state: ink-mute (clean), accent (dirty), warn (diverged).

UIRibbon + per-folder icon are automatic. Hover the icon to see the chip; right-click for context menu.

39

Dirty-file dots on changed files

v0.7.0: any file in the Navigator that's dirty per git status gets a small orange dot to the right of its name. Hover the dot for the STATUS-DIFF tooltip — e.g. "Modified · +42 / -7". Refresh is fsevents-driven so dots update within ~150ms of a save (bounded depth, common caches like .next / node_modules ignored). Repo-root folders show their roll-up via the ribbon (item 17c); individual files show their own status.

UIVisible automatically when in a repo; hover the dot for diff stats.

40

Open a file or folder on GitHub from the Navigator

v0.7.0: right-click any file or folder inside a GitHub-remote repo. Two new menu items: Open on GitHub (opens the file's blob page or folder's tree page in your default browser) and Copy GitHub URL (clipboard, no browser). Works for github.com AND Enterprise hosts (github.<company>.com auto-detected from the remote URL). Same items show up when right-clicking the git ribbon at the top of the tree.

UIRight-click → "Open on GitHub" or "Copy GitHub URL".

41

Clone a GitHub repo from inside Duo

v0.7.0: File menu → Clone from GitHub… opens a modal. Paste a URL (https://github.com/owner/repo or owner/repo) plus a parent directory; the repo name is derived. The Navigator's current cwd is the default parent. Pre-flight collision check fires while you type — if the target folder already exists, an amber warning shows above the inputs with a "Reveal existing folder in Finder" button and the Clone button stays disabled. On success, the Navigator jumps to the new folder. Right-click any folder in the Navigator for "Clone GitHub repo here…" to skip the parent-dir picker.

UIFile menu → Clone from GitHub… · or right-click in the Navigator → Clone GitHub repo here… · or duo git clone <url> --target-dir <path> for the CLI surface.

42

Create a new file or folder from the navigator

v0.7.7: three ways to create a new file or folder without leaving the navigator. Right-click the breadcrumb for New file here… / New folder here… (uses the right-clicked segment's directory as the default location). File menu has the same two entries (defaults to the currently-focused navigator dir). Or use the chord — ⌘N for new file, ⌥⇧⌘N for new folder (moved off ⇧⌘N, which is now vault quick-capture — ENH-208). All three triggers reuse the same flow: inline rename on the new row, validates filename collision, scrolls into view.

UIRight-click the breadcrumb → New file/folder here · File menu → New File… / New Folder… · ⌘N / ⌥⇧⌘N chords.

43

Show or hide hidden files (dotfiles)

v0.7.7: the navigator hides dotfiles (.gitignore, .env, .DS_Store, etc.) by default. Toggle via the View menu's Show Hidden Files checkbox, the ⌘⇧. chord (Finder convention), or the CLI verb. The .claude and .obsidian directories stay always-visible regardless (Duo + Obsidian-vault workflow needs them).

44

Reopen the tab you just closed

v0.7.7: ⌘Z reopens the most recently closed tab — works for file tabs (markdown editor / canvas / image / PDF), browser tabs, and terminal tabs. Smart-routed so text undo still wins inside the editor, address bar, dialogs, and the browser pane's own inputs. Bounded to the 10 most recently closed tabs per session.

UI⌘Z when no text field is focused.

45

See your projects in a left-edge rail

v0.7.10: a thin left-edge rail surfaces one tile per detected project plus an "All" tile. A folder qualifies as a project when it's a git repo root OR contains CLAUDE.md/.claude/ AND you're working in it (at least one terminal cwd or non-pinned tab under it). Tiles render in the locked R1-B "quiet bloom" treatment — paper bg + colored initials + same-hue underline when unfocused. The six hues (pine / harbor / iris / plum / rose / moss) are hash-stable per repo path, so the same project always lights up in the same color. v0.8.1: tile labels are now word-aware + collision-free — ai-platform / ai-models / aipm-dashboard / aipm-tools render as AP / AM / AD / AT instead of all collapsing to a duplicate AI. Pure two-phase algorithm (letter-initial ladder, then numeric suffix); see shared/projects.ts § computeProjectAbbreviations.

UIVisible automatically when you have at least one qualifying project open. Rail hides entirely when nothing qualifies.

46

Focus on one project to hide unrelated tabs

v0.7.10: click any project tile to focus that project. The tile blooms to full hue + a white left-edge notch; a Focused: <project> × chip appears in the titlebar. Visibility-only filter: non-member terminal + working tabs disappear from the strips while their PTYs and editor state stay alive in the background. Navigator re-roots to the project root (soft re-root — you can still navigate up/out). Ctrl-Tab cycles only visible terminal tabs. Pinned cross-project tabs (tasks.md, idle-thoughts.md, etc.) stay visible across every focus by design. Click the active tile, the All tile, or the chip × to release.

UIClick a project tile to focus; click the active tile / All / chip × to release.

47

Auto-spawn a terminal when focusing a project with none

v0.7.10: if you focus on a project that has working tabs but no terminals, Duo automatically spawns a fresh terminal at the project root — kind matches your most recent manual choice (shell or claude). No more empty terminal strip after a project switch. Per-focus-session guard prevents double-spawn on rapid refocus.

UIAutomatic. Click a project tile with no member terminals → terminal appears at the project root.

48

Pin a project tile + bulk-close from the rail

v0.8.0: right-click any project tile to manage it. Two items: Pin to rail (or Unpin when already pinned) keeps the tile in the rail even after every member tab/terminal closes — useful for projects you re-visit often. Pinned tiles render a small color-matched dot in the top-right corner. Close N terminals and M tabs atomically flushes every member tab + terminal in one click; the count is live. When any member terminal is a claude-kind tab, a confirm dialog appears so a misclick doesn't end a live session. The pin set persists in ~/.claude/duo/projects.json.

UIRight-click a project tile in the rail.

49

Open a file from another project → focus auto-switches

v0.8.0: while focused on one project, opening a file from a different project (via the navigator, duo edit, duo open, ⌘N) auto-switches focus to that file's project. The title-bar focus chip flips, the navigator re-roots, and the visibility filter follows. Reactivating an already-open tab also triggers the switch — the heuristic is "where is the user looking now" not "did a new tab appear."

UIAutomatic on every file open while a focus is active. CLIduo edit <path> or duo open <path> — same behavior.

50

Browser tabs respect the project focus (file:// only)

v0.8.0: browser-mode canvas tabs whose URL is a file:// path now obey the same focus filter as file editor tabs. Hide a /tmp/test.html tab when you focus the duo project; it reappears in All mode. Non-file URLs (http, https, about, etc.) cross focuses by design — web pages are treated as reference material. Pinned browser tabs (e.g. What Duo Does, the smoke-walk pages) also cross focuses regardless of path.

UIAutomatic. Browser tabs in the working-pane strip show / hide with focus.

51

Drive the project rail from the CLI

v0.8.0: every rail action has a duo project counterpart so agents can drive the focus lens. Name resolution is case-insensitive against unique project names; exact root paths always match.

CLI duo project list (snapshot — derived projects + focused + counts) duo project focus <name|root> (set the focus lens) duo project focus --all (release focus) duo project pin <name|root> (persistent rail tile) duo project unpin <name|root> duo project close <name|root> (bulk close member tabs + terminals; confirms on claude-kind)

53

Paste into the terminal without auto-executing

When you copy a command from chat or a doc, the source usually appends a trailing newline. Pre-v0.6.7, pasting that into a Duo terminal auto-executed the command before you could read it. Now Duo strips trailing newlines from the clipboard payload (matches Terminal.app's default). Internal newlines stay intact — multi-line paste for Claude Code prompts, heredocs, REPL blocks, and shell scripts still works. v0.6.7+

UIJust paste (⌘V). The trailing newline is dropped automatically; no opt-in required.

UIClick + on the terminal tab strip, or ⌘⇧T from anywhere. CLIduo new-tab --claude

55

Open a second window — each with its own workspace

v0.10.0: Duo now opens a genuine second window. File → New Window (⌥⌘N) or duo window new spins up another app window — and it opens blank, with its OWN workspace, browser pane, navigator, terminals, and geometry (it does not clone window 1's pinned tabs). Each window's full state is restored across relaunches. Gated by an Allow Multiple Windows setting in the Settings menu (default on); when off, the menu item is disabled and duo window new exits non-zero with a clean disabled error. To drive a specific window from any terminal, every Duo terminal carries a DUO_WINDOW env stamp, and the global --window N flag targets window N — an unknown id falls back to the primary (lowest-id) window.

UIFile → New Window (⌥⌘N); toggle availability via Settings → Allow Multiple Windows. CLIduo window new (open another window) · duo windows (list open windows as JSON — [{id, primary, focused, activeWorkspace}]) · duo --window <N> <verb> (address window N from any terminal).
