The Rollup Guide

Duo Living views over your notes — companion to the Vault Guide
What is a rollup? A rollup is a question you ask your notes once and keep asking forever: “every open task, grouped by status” · “milestones by initiative” · “who owns what.” You build it by pointing and clicking — pick the kind of notes, how to group them, what to filter out — and Duo keeps the answer current as your notes change. Each rollup is also a web page you can share, and it lives in your vault as a plain file, so it travels with your repo like everything else. No database, no export step, nothing to maintain.

1One rollup, three places you'll meet it

Every rollup is a single saved question that shows up in three ways:

The one thing worth remembering: the Rollups tab is always live — it re-answers the question every time you look. The rollup page is a snapshot from the moment it was rendered. That difference is all “fresh” and “stale” ever mean (§ 6).

2Creating your first rollup

Three ways in, easiest first:

Start from what you have — the Entities section

The Vault tab ends with Entities: every kind of note in your vault with a live count (task 14 · person 7 · initiative 3…). Click one. Duo opens the Rollups tab showing every note of that kind, instantly — nothing saved yet. If the view is useful, click Save as rollup and it becomes permanent; then shape it (§ 3).

Start from scratch — “+ New rollup”

On either the Vault tab or the Rollups tab. Duo creates an untitled rollup over your vault's main note type, opens it in the Rollups tab, and puts your cursor in the Title field — name it and go.

Start from a conversation — right-click “+ New rollup”

Choose Start a Claude authoring session… and describe what you want in plain language. Claude writes the rollup for you — the way to get things the point-and-click builder doesn't do, like computed columns (§ 8).

The Roll Up panel on the right is the whole definition, always visible:

  • Title — the rollup's name everywhere. Renaming is just typing here.
  • Types — which kinds of notes to include (tasks, milestones, people… one or several).
  • Group by — how rows bundle. Add more than one level and groups nest — by initiative, then by status.
  • Filters — keep only what matters: a field is / is not a value, or is set / is not set. Value pickers offer only values that actually appear in your notes.
  • Columns — which fields show in the table.

Every change takes effect immediately: the view re-computes, the file is saved, and the shareable page is re-rendered. There is nothing to remember to do.

4Editing your notes from a rollup

A rollup isn't read-only — it's a workbench over the notes it shows:

  • Hover a row to see where that note lives in the vault.
  • Click a row to open the note itself.
  • Select a row (the ✎ mark) and its fields appear in the panel — flip a status, reassign an owner, tick a checkbox. The change writes straight into the note, the row re-files into its new group, and an Undo chip waits in case you fat-fingered it. (Duo's file history keeps every prior version regardless.)
So a triage session looks like: open “Open tasks” → select a row → flip status → watch it move to the right group → next row. No files opened, no YAML touched.

5The rollup page

Under the rollup's title in the Rollups tab sits a small path — rollups/open-tasks.html. That's the rollup's page: a self-contained web page with the same grouped tables, a “What changed” log, and a Copy as Markdown button. Click the path to open it. It needs nothing but a browser, so it's the thing you commit, push, and send to people (§ 9).

When a rollup page is open in Duo's browser, Duo adds a slim bar above it:

Refresh re-makes the page from your notes as they are right now · Edit jumps to the Rollups tab

The bar always tells you when the page was made and whether your notes have changed since. Refresh is greyed out when there's nothing to do; it lights up the moment the page falls behind. This bar comes from Duo, not the page — it works even on pages rendered long ago.

6Fresh and stale

“Stale” means one thing: some note changed after this rollup's page was last made. The live view in the Rollups tab can't be stale — it's recomputed every time you look. Only the page can fall behind, the way any printout does.

Three things to know:

  • Stale is normal. You and Claude edit notes all day; pages fall behind. It just means “refresh before you share this file.”
  • Any Refresh fixes it. The Rollups tab's Refresh and the page bar's Refresh both bring the page current in one click, and every fresh/stale chip updates immediately.
  • It's deliberately strict. Duo compares against the whole vault, so an edit to an unrelated note can mark a page stale even though its rows wouldn't change. Refreshing such a page is instant and harmless.

Each row in the Rollups tab's list carries a ⋯ menu (also on right-click):

Open definition noteOpens the underlying file (§ 10) — read-only curiosity; you never need to edit it.

For the collection at a glance, the Vault tab lists every rollup with its freshness chip — click a name to read the page, click Edit to work on it — and the Entities section below shows what your vault contains, ready to become new rollups (§ 2).

8When Claude writes the rollup

The point-and-click builder covers the common shapes. For anything richer — computed columns, unusual queries, multiple views in one page — ask Claude (right-click “+ New rollup” → Start a Claude authoring session…, or just describe what you want in any Duo terminal).

A Claude-written rollup is a first-class citizen: it lists, renders, refreshes, and shares like any other. The one difference: if its query uses features the builder doesn't have, the Roll Up panel shows it as view-only instead of editable — with two ways forward:

  • Normalize with Claude — a button on the view-only notice. Claude rewrites the rollup into the builder's simpler form without changing what it shows (anything that can't be expressed is preserved as a note inside the file, and Claude reports what moved). After that, it's fully editable in the panel.
  • Leave it — and keep evolving it through Claude.

And if a rollup's file ever gets damaged (a bad hand edit, a merge conflict), Duo shows a doctor card instead of an error wall: one click on Fix with Claude spawns a session that repairs it and reports what it did.

9Sharing — Markdown & GitHub

Copy as Markdown

On every rollup page. One click puts the whole rollup on your clipboard as a Markdown table, ready to paste into an issue, a PR description, a doc, a chat. If your vault lives in a GitHub repo, each row links to the note's GitHub page automatically.

Publishing the page itself

WhereWhat to expect
Sent as a file / opened anywhereThe page is self-contained — it renders in any browser, styling included.
In a GitHub repoGitHub shows HTML files as source code, not pages. For reading inside a repo, paste the Copy-as-Markdown output into a .md file instead.
On GitHub PagesThe page renders fully. Turn on “GitHub links in rendered page” in the Roll Up panel first — then every row links to the note's GitHub page (otherwise links point at raw files).

10Under the hood (and the command line)

There's no magic to trust: each rollup is one small markdown file in your vault's rollups/ folder holding the question, next to the rendered page. Both travel with your repo; both are rebuildable at any time. You never need to edit the file by hand — the builder, Claude, and the command line all write it for you (and the doctor fixes it if something else breaks it).

Command-line equivalents

Everything above has a terminal twin (useful for agents and automation — they work in any shell, no app needed):

duo rollup list                 # every rollup + freshness
duo rollup new --type task --group status --title "Open tasks"
duo rollup show <note>          # the parsed definition
duo rollup set <note> --filter 'status!=done' [--links github|relative]
duo rollup render <note> [--github]   # re-make the page
duo rollup markdown <note>      # the Copy-as-Markdown table, to stdout
duo rollup diff <note>          # what changed since the last page
duo rollup duplicate <note>
duo rollup delete <note> --force
duo rollup doctor <note>        # diagnose a broken one

Full verb documentation: rollup.md in this folder (the agent-facing reference), or duo --help.
